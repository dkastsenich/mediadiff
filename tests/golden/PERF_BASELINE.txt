# tests/golden/PERF_BASELINE.txt -- the committed instruction-count ratchet
# baseline for PERF-03/PERF-05 (05-12-PLAN.md Task 2, D-14/D-15).
#
# What each line records: leg, metric, value, and the commit at which the
# value was measured -- one line per metric, format:
#
#   leg=<leg> metric=<metric> value=<retired-instruction-count> commit=<short-sha>
#
# `<leg>` is always the one designated leg this file is scoped to
# (x64-linux, the same leg tests/golden/CORPUS_DIGEST.txt and the five
# byte-exact fixture-derived goldens are scoped to -- see
# tests/golden/README.md). `<metric>` is either `plain_instructions` (the
# baseline PacketScan-alone sweep) or `full_instructions` (the same sweep
# plus every registered timeline_*_analyzer()'s own run, D-16's "full
# metadata-plus-timeline analyzer set"). `<value>` is the retired
# instruction count `valgrind --tool=cachegrind` reported for that leg
# against the D-16 ten-minute 1080p reference file.
#
# CI is READ-ONLY against this file (D-15). scripts/measure_timeline_perf.sh
# --check-baseline never writes here -- it only READS these lines, compares
# them against a freshly measured value, and on a regression prints the
# exact pasteable replacement line to stderr. A HUMAN pastes that line into
# this file, in a reviewed commit, exactly as tests/golden/README.md's
# UPDATE_GOLDENS contract already works for renderer goldens (Phase 2
# D-12) -- CI measures and compares, a human decides whether the new
# number becomes the new baseline. This file's own git history IS the
# regression-tracking-over-time PERF-05 asks for: no external service, no
# bot push, no gh-pages branch, which is also what keeps a fork pull
# request able to run this gate at all (D-15's own rejected alternatives:
# github-action-benchmark on gh-pages writes to the repo and breaks on
# forks; artifacts-plus-job-summary-only loses history outside the Actions
# retention window).
#
# Exceeding a recorded value by more than
# PERF_RATCHET_TOLERANCE_PERCENT (scripts/measure_timeline_perf.sh) is a
# hard CI failure on the designated leg; staying within it, including an
# improvement, is not gated -- a ratchet tightens only by human review of
# the printed pasteable line, never automatically.
#
