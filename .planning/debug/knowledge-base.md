## corpus-fixture-byte-drift — "76 of 81 fixtures drifted" was a golden-provenance mismatch, not a generator regression
- **Date:** 2026-09-10
- **Error patterns:** fixture byte drift, CORPUS_DIGEST.txt mismatch, byte-exact golden mismatch, `size.file` golden expects 350551 got 351486, unit.inspect_container golden failure, unit.ts_scan_golden ts_204/ts_multiprogram/ts_single, integration.size_checks pinned golden, "identical GENERATOR_MANIFEST.json but different bytes", `-flags +bitexact -fflags +bitexact` still nondeterministic, phantom regression, 5 of 637 tests failing after regenerating the corpus
- **Root cause(s):** AND-gate, both conditions required. (1) ENVIRONMENT *[corrected 2026-09-18, see Correction below]*. The pinned FFmpeg 9.0.1 static build's encoder output is host-dependent. `-flags +bitexact -fflags +bitexact` fixes header/metadata determinism but does NOT pin libavcodec's AUTO encoder slice-thread count (nb_cpus+1: 9 on the 8-CPU workstation, 5 on 4-vCPU GitHub runners). The `tags_volatile_*` recipes also parse a zone-less `creation_time` in local TZ. The DSP path changes bytes too (proved on one unchanged binary: `-cpuflags 0` moves `tracer_a.mp4` from 141218 to 141194 bytes, while `-avx2`/`-avx512`/`-avx512icl` do not). But the DSP path separates architectures (arm64 NEON vs x86), not this x86 workstation from the x86 runner. (2) PROCESS — `tests/golden/*` and `tests/golden/CORPUS_DIGEST.txt` are deliberately captured on the GitHub x64-linux runner (`bc09705`, `64bc168`) while `ctest` on a developer workstation compares them against locally regenerated fixtures, and nothing in the repo records which host a golden came from, so the inevitable mismatch surfaces as "your generator regressed" instead of "these goldens are not yours". There was no drift at all: the workstation's 2026-09-10 bytes are identical to its 2026-09-05 bytes (`13ea9db`'s golden `size.file 351486`, reproduced exactly).
- **Correction 2026-09-18 (session test-898-ci-nonreproducible, `.planning/debug/resolved/test-898-ci-nonreproducible.md`):** Cause (1) originally said the flags do "NOT neutralise runtime SIMD dispatch in the DSP paths" and made SIMD dispatch the workstation-vs-runner difference. That is wrong for x86. The difference is libavcodec's AUTO encoder slice-thread count (nb_cpus+1: 9 vs 5), plus TZ for the `tags_volatile_*` `creation_time` fixtures. Evidence: under `-cpucount 4` + `TZ=UTC`, the AVX-512 workstation reproduces 162/164 designated-leg hashes. The only mismatch is the already-excluded libopus pair (WINDOWS #22). The two `timeline_ts_jump*` hashes were predicted locally before CI computed them, and designated-leg run 35347044190 matched them exactly. The `-cpuflags 0` observation still stands: the C DSP path does change bytes. Cross-architecture differences (arm64 NEON vs x86) remain DSP-path dependent. Cause (2), the Fix, and the Recurrence guard are unaffected. The original session file in `resolved/` is left as written.
- **Fix:** Moved the designated-leg policy out of `.github/workflows/ci.yml`'s `ctest -E` regex and into the test harness so it governs and explains itself on every run. New `check_golden_designated_leg()` + pure `designated_leg_golden_action(designated_leg, update_goldens)`: byte-for-byte when `MEDIADIFF_DESIGNATED_LEG` is set and non-empty (assertion never loosened), otherwise `SKIP()` carrying the full reason (golden class, host-dependence, "a mismatch here is EXPECTED", the WINDOWS.md entries, how to assert deliberately), and `UPDATE_GOLDENS` refused on EVERY leg naming the `13ea9db`/`bc09705` precedent. Five call sites switched. `ci.yml` sets the var on the designated leg plus two anti-silent-skip guards (fail if any of the five is `Skipped`; fail if none of the five appears at all, so the guard cannot silently check nothing; errexit suspended across the pipeline on purpose so a failing ctest cannot kill the step at the pipe and skip both guards). No golden re-baselined, no fixture regenerated, `scripts/gen_corpus.sh` untouched.
- **Files changed:** tests/support/golden.h, tests/support/golden.cpp, tests/unit/test_golden.cpp, tests/unit/test_ts_scan_golden.cpp, tests/unit/test_inspect_container_section.cpp, tests/integration/test_size_checks.cpp, .github/workflows/ci.yml, tests/golden/README.md, .planning/WINDOWS.md
- **Why not caught:** No gate existed for this class. The condition was already fully known — `.planning/WINDOWS.md` **#12** recorded it verbatim on 2026-09-05T17:25:14Z, condition and prescribed procedure both — but was left OPEN with nothing built to make it self-announcing. The policy lived only as a `ctest -E` regex in CI, a place that cannot reach anyone running `ctest` directly, and the five tests' own failure text recommended `UPDATE_GOLDENS=1` — the one remedy that must never be applied to this class, and exactly the mistake `13ea9db` made. Rediscovered 5 days later as a phantom regression; cost Phase 4 paused at 1/12 plans plus a full debug session, for a non-defect.
- **Recurrence guard:** (a) `tests/support/golden.cpp` `check_golden_designated_leg()` / `designated_leg_golden_action()` — policy in the harness, self-explaining skip off the designated leg, `UPDATE_GOLDENS` refused on every leg; (b) regression tests `tests/unit/test_golden.cpp` — four-cell truth table, env boundary (unset/empty/"1"/"x64-linux"), skip-reason wording assertion (3/3 mutants at the fix site killed); (c) two anti-silent-skip guards in `.github/workflows/ci.yml`; (d) `tests/golden/README.md` documenting the two golden classes and the only correct refresh path; (e) this KB entry.
- **Known remaining hazard (approved follow-up, NOT fixed here):** `scripts/gen_corpus.sh:27` `FFMPEG_BIN="${MEDIADIFF_FFMPEG:-ffmpeg}"` still falls back to whatever `ffmpeg` is on `PATH`. Deliberately out of scope during diagnosis (changing it would alter the thing under investigation); a separately approved task will harden it to fail loudly on an unpinned PATH ffmpeg. **Update 2026-09-10 (quick 260910-vvp):** the follow-up landed. `scripts/gen_corpus.sh` now sources new `scripts/resolve_pinned_ffmpeg.sh`, which resolves `MEDIADIFF_FFMPEG` override -> the repo-local pinned install under `.ffmpeg-pinned/` -> `PATH` (PATH stays permitted, never prohibited -- CI's Windows PowerShell cross-check depends on it), and gates on a release-identity check: the selected binary's reported release triple must match `scripts/ffmpeg_pin.json`'s `version`, or the run aborts before any fixture byte is written. The escape hatch is `MEDIADIFF_ALLOW_UNPINNED_FFMPEG` (downgrades the mismatch to a loud warning; no workflow file sets it). New `scripts/test_gen_corpus_pin_gate.sh` (seven cases, wired into CI's lint job) and `tests/golden/README.md`'s new "The corpus must come from the pinned generator" section round out the two new files.

- **Transferable heuristic:** When an investigation ends in "known, documented, left open", the deliverable is not the ledger entry — it is the artifact that makes the condition announce itself where someone will next trip over it. It fixes headers/metadata, not the encoder's auto thread count, not local-time parsing, and not (across architectures) the DSP path. *[Corrected 2026-09-18; originally "not SIMD dispatch".]* And when a golden and its subject can come from different hosts, the provenance must be recorded next to the golden or the mismatch will be misread as a regression.

## test-898-ci-nonreproducible — declared-set test green locally, red on CI x86: the fixture pair straddled a tolerance line and its bytes depend on the auto encoder thread count
- **Date:** 2026-09-18
- **Error patterns:** passes locally fails on CI, expect_declared_set, "declared id(s) occurring FEWER times than declared among the report's non-pass findings", size.stream_bitrate warn vs pass, 3% warn threshold, workstation vs CI runner fixture bytes differ, timeline_ts_jump.ts, timeline_ts_nowrap.ts, mpeg4 encoder output differs per host, x64-linux and x64-windows-static-md fail but arm64-osx passes, "tol comparator: delta_num (num * den cross-products) overflowed int64_t during cross-multiplication; cannot determine a verdict", timeline.av_drift status=error, int64 overflow in rational cross-multiplication, test pins status=error as an expected finding
- **Root cause(s):** The flake is an AND-gate; both conditions were required. (1) ENVIRONMENT: the mpeg4 fixture bytes depend on libavcodec's AUTO slice-thread count (nb_cpus+1: 9 on the 8-CPU workstation, 5 on 4-vCPU GitHub runners) and, secondarily, on the DSP path (x86 SIMD vs C/NEON). (2) DATA: the nowrap/jump pair's video size.stream_bitrate delta sat at +2.4%..+3.2% across generation configs, straddling the 3% warn line (workstation 3.18% warn, CI x86 2.77% pass, arm64-osx >= 3% non-pass). There was also a separate CODE bug. `src/compare/tol.cpp` cross-multiplied rationals in int64_t and returned status=error on legitimate timeline.av_drift rationals (270183060000 x 36327640 > INT64_MAX), and four tests pinned that error as expected. Side finding: WINDOWS #12's workstation-vs-runner drift is thread count + TZ, not SIMD. Under `-cpucount 4` + `TZ=UTC`, 162/164 fixtures reproduce the designated leg; see the Correction on corpus-fixture-byte-drift.
- **Fix:** (a) `scripts/gen_corpus.sh` jump recipe: seg_b `-output_ts_offset 3.0 -> 5.0`. Video is now -27% and audio -42% on every one of 10 generation configs, a ~16.6pp margin vs a ~0.6pp host spread. Test 898's declared set is unchanged. The two changed fixture hashes went through `CORPUS_DIGEST_PROVISIONAL.txt` and were transcribed from designated-leg run 35347044190 (a56dd9b), never regenerated on a workstation. (b) New `src/core/exact_int.h` (portable 32-bit-limb 256-bit sign-magnitude integer). `tol.cpp` now compares exactly, a strict extension of the int64 path with messages byte-identical whenever the values fit. Tests that pinned status=error now assert exact verdicts with boundary neighbours. (c) WINDOWS #29 (the tol message prints the absolute delta with a `%` suffix) and #30 (#26's symptom is now fail instead of error) were recorded, not fixed. Commits 9ce943d, e55c829, fb84c7b, 8c343c7, a56dd9b.
- **Files changed:** src/core/exact_int.h (new), src/compare/tol.cpp, tests/unit/test_exact_int.cpp (new), tests/unit/CMakeLists.txt, tests/unit/test_compare_semantics.cpp, tests/unit/test_tolerance.cpp, tests/integration/test_timeline_structure.cpp, tests/integration/test_doc03_coverage.cpp, scripts/gen_corpus.sh, tests/golden/CORPUS_DIGEST_PROVISIONAL.txt, tests/golden/CORPUS_DIGEST.txt (designated-leg transcription only), .planning/WINDOWS.md
- **Why not caught:** For the near-threshold fixture, no gate existed for this class. Local ctest only ever sees workstation bytes, and nothing measures a declared set's margin from tolerance lines across generator configurations. The designated-leg CI gate did catch it, which is why it blocked PR #6. The int64 overflow was masked by the test gate itself: unit CR-03 tol, unit tolerance widening, integration Test 9 and test 898 all asserted status=error as expected behaviour. 05-10's `detail::Int128Accum` fixed the least-squares fit, and no one swept the sibling comparator.
- **Recurrence guard:** (a) `tests/unit/test_exact_int.cpp`: 5 `[exact_int]` cases. (b) `tests/unit/test_tolerance.cpp`: "tolerance: timeline.av_drift's real splice rates, whose cross-products exceed int64, get the exact verdict" (real rationals + 0.2 boundary neighbours) and "tolerance widening: a tolerance magnitude whose 3x widening exceeds int64 is widened exactly ...". (c) `tests/unit/test_compare_semantics.cpp`: "semantics: CR-03 tol comparator returns the exact verdict when num*den cross-products exceed int64_t, ...". (d) `tests/integration/test_timeline_structure.cpp`: the "unflagged jump trigger pair" and "flagged/unflagged split pair" declared sets no longer contain an error-status id. (e) `scripts/gen_corpus.sh:1863` `-output_ts_offset 5.0`, the data margin. (f) The existing designated-leg digest assert + PROVISIONAL transcription + `scripts/lint_corpus_digest_provenance.sh`. The global `-cpucount 4` + `TZ=UTC` generator change (D2, 0 designated-leg hashes change) is filed separately.

Round 1, run 35347044190 (head 8c343c7): x64-linux failed the digest assert on exactly the two predicted lines, and its computed hashes equalled the locally predicted d2ba0765.../cce78b1a.... - **Related ledger entries:** WINDOWS **#12** (cause corrected; wording fix belongs to the D2 follow-up), **#20** (same class: fixture calibrated near a tolerance line), **#22** (libopus, still host-dependent, digest-excluded), **#26/#29/#30** (tol comparator and message), **#11/#14** (pre-existing CI infra, out of scope).
- **Transferable heuristic:** A declared-set test is only as machine-independent as its tightest finding's margin to a tolerance line. Measure that delta's spread across generator configs (`-cpucount N` for threads, `-cpuflags 0` for the C/NEON-like path) and keep the margin an order of magnitude above it. When fixture bytes differ between hosts, check the encoder's auto thread count before blaming SIMD: `-cpucount N` reproduces an N-CPU host's bytes exactly, and that is also how to predict a CI leg's hashes before it runs. Never declare `status=error` as an expected finding; that pins a defect as the contract.
