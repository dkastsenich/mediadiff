**1. `src/util/fs.h` — add `mediadiff::getenv_utf8`.**

Add `<cstdlib>`, `<memory>` and `<optional>` to the header's existing standard-include block. Place the new function after `rename_replace_utf8` and before `enable_vt_output`, following `rename_replace_utf8`'s shape: one function with one doc comment and an internal `#ifdef _WIN32` split (not two separately-documented bodies in the file's outer platform branches).

Signature: `inline std::optional<std::string> getenv_utf8(const char* name)`.

Windows branch: declare a `char*` buffer initialised to `nullptr` and a `std::size_t` count initialised to zero, call `_dupenv_s` with their addresses and `name`, and capture the return value. Immediately wrap the buffer in a `std::unique_ptr<char, decltype(&std::free)>` constructed with `&std::free`, so the CRT allocation is released on every exit path — including one where the `std::string` construction below throws. Then: a non-zero return means a genuine failure, return `std::nullopt`; a null buffer means the variable is unset, return `std::nullopt`; otherwise return a `std::string` constructed from the owned pointer. A set-but-empty variable arrives as a non-null pointer to a single NUL byte, so that last branch returns an engaged optional holding the empty string — which is the whole point.

Non-Windows branch: read with the standard C library's environment accessor into a `const char*`, return `std::nullopt` when it is null, otherwise return a `std::string` built from it.

The doc comment must carry, in the header's existing explanatory register, all of the following — this is the file where the reasoning now lives, since the call-site comment it replaces is being deleted:

- The return contract: unset maps to `std::nullopt`, set-but-empty maps to an engaged optional holding `""`. That distinction is load-bearing — `ColorInputs`' three `std::optional<std::string>` fields exist for it, `NO_COLOR`'s convention is that PRESENCE is the signal rather than the value, and the WR-02 regression tests assert it.
- Why `_dupenv_s` rather than the deprecated C accessor: MSVC's CRT deprecates the latter (C4996) and `/W4 /WX` (BUILD-05) promotes that to a hard error, which is exactly why `_wfopen_s` sits a few lines above in this same header (commit 47d5965). Say plainly that `_CRT_SECURE_NO_WARNINGS` is not an alternative — it would disable a whole deprecation class repository-wide to hide one call.
- Why `_dupenv_s` rather than `getenv_s`: both preserve the unset-versus-empty distinction, but `getenv_s` needs a two-call probe whose size-probe returns `ERANGE` as a non-error, while `_dupenv_s` is single-call and its null-buffer-means-unset maps one-to-one onto the null-pointer shape every existing call site already tested for.
- Ownership: `_dupenv_s` allocates and the caller must release; the `unique_ptr` does that before return, so no path leaks.
- Encoding honesty. The narrow form reads the CRT's active-code-page view of the environment. Inside the `mediadiff` executable, `app.manifest`'s `activeCodePage` makes that UTF-8; the two test executables carry no manifest (CMakeLists.txt attaches it to `mediadiff` only), so there it is the machine's ambient ANSI code page. Every variable read through this shim today — `NO_COLOR`, `CI`, `GITHUB_ACTIONS`, `MEDIADIFF_DIR_TEST_INJECT_INTERNAL_ERROR`, `UPDATE_GOLDENS`, `PATH` — is ASCII in practice, so narrow is adequate rather than merely convenient. If a non-ASCII value ever matters, the encoding-exact upgrade is `_wdupenv_s` fed through this header's own `wide_to_utf8`, and it can only live in this file, because this header and `src/cli/main.cpp` are the only two places in the repository permitted to name wide-character types.
- Why the parameter is a `const char*` rather than this header's usual `std::string_view`: both CRT entry points require a NUL-terminated name and every caller passes a literal, so a `string_view` would only add an allocation.

**3. `tests/unit/test_fs_utf8.cpp` — prove the contract.**

This is the only automated evidence that the unset-versus-empty distinction survives, and on the Windows leg it is the only thing that will ever convert `_dupenv_s`'s documented behaviour from an inference (the debug session could not execute MSVC) into a CI-verified fact. It belongs here rather than in a new file because this suite already covers `src/util/fs.h` and is already registered in `tests/unit/CMakeLists.txt`.

Add `<cstdlib>` to the includes. In the file's anonymous namespace add two helpers that return `bool` success:

- a setter taking a name and a value: under `_WIN32` call `_putenv_s` (the non-deprecated secure variant) and return whether it reported zero; otherwise call `setenv` with an overwrite flag of 1 and return whether it reported zero.
- a clearer taking a name: under `_WIN32` call `_putenv_s` with an empty value, which is how Win32 removes a variable; otherwise call `unsetenv`. Return whether it reported zero.

Add a new `TEST_CASE` named exactly `test_fs_utf8 - getenv_utf8 separates unset from set-to-empty`, using a variable name unique to this test (`MEDIADIFF_TEST_ENV_SHIM`) so no other test in the process can observe it, and clearing it at both the start and the end of the case so a partially-unwound `REQUIRE` cannot leak state into a later test. Sections:

- After clearing, `getenv_utf8` on that name returns a disengaged optional.
- After setting it to a non-empty value, `getenv_utf8` returns an engaged optional holding exactly that value.
- Under `#ifndef _WIN32` only: after setting it to the empty string, `getenv_utf8` returns an engaged optional holding the empty string. The section's comment must say WHY it is POSIX-only — the Win32 environment API cannot represent a set-but-empty variable at all, since both `_putenv_s` with an empty value and `SetEnvironmentVariable` with an empty value DELETE the variable. The case is unreachable on Windows by construction, not merely unexercised there.

Check every setter/clearer return with `REQUIRE`, so a silently-failing environment mutation cannot turn into a vacuously passing assertion.
