naming the required version, since `tomllib` landed in 3.11. Arguments:
`--checks`, `--docs-dir`, `--out-dir`. `checks.def` is TOML-syntax despite the
`.def` name mandated by doc 01 section 2; record that in a header comment in the
file. Each entry is an `[[check]]` array-of-tables record with keys `id`,
`group`, `semantic`, `unit`, `value_kind`, `severity`, `tolerance` (optional),
`volatile` (optional bool), `requires_pass` (optional bool). Seed exactly the

`<intrin.h>` on MSVC, behind one `#if defined(_MSC_VER)`. No libav header is
included anywhere under `src/core/` or `src/compare/` (D-07).

`pass` (ENG-14). Dump with an explicit indent so the text is stable. This is a
pure function: it neither opens a file nor writes to a stream.

## Sequencing rationale

Phase 2 runs eleven plans in eleven waves, one plan per wave, with no two plans
executing concurrently. That is deliberate, and it is recorded here rather than
only in the planner's return message so that anyone reading the plans can see why
no parallelism was attempted.

**Every plan writes the shared CMake source lists.** Each plan appends its new
`.cpp` files to `add_library(libmediadiff STATIC ...)` in `CMakeLists.txt`, its
new unit tests to `add_executable(mediadiff_unit_tests ...)` in
`tests/unit/CMakeLists.txt`, and its new integration tests to
`add_executable(mediadiff_integration_tests ...)` in
`tests/integration/CMakeLists.txt`. These are concurrent **appends to the same
source lists**, not merely concurrent reads — two plans running in the same wave
would each rewrite the same list region from a stale base and one set of sources
would silently vanish from the build. Consequently no two plans in this phase have
disjoint `files_modified`, and the wave assignment rule (same-wave plans must have
zero `files_modified` overlap) forces one plan per wave on its own.

**The nearest-looking parallel candidates overlap in real source files too**, so
even a hypothetical fix to the CMake contention would not free them:

| Candidate pair | Overlapping files |
|---|---|
| 02-05 ∩ 02-06 | `src/core/policy.h`, `src/core/policy.cpp` — 02-05 writes layers 1-2 of the precedence merge, 02-06 extends the same `resolve_policy` to layers 3-4 |
| 02-04 ∩ 02-05 | `src/compare/engine.cpp` — 02-04 adds the semantic dispatch arms, 02-05 adds the severity/volatile resolution the dispatch consults |

**The layering is a genuine dependency chain regardless.** The phase builds
model -> registry -> semantics -> policy -> snapshot -> reports -> CLI -> `dir`,
and each stage consumes types and functions the previous stage introduces: the
semantics need `CheckDef` and `Value`; policy resolution needs the semantics'
`Tolerance`; the report model needs resolved `Finding`s; the CLI needs the
renderers; `dir` needs the whole single-file path working. Removing the CMake
contention entirely would therefore not unlock a single additional parallel pair —
it removes no parallelism that existed. The serialization costs nothing beyond
what the dependency graph already imposed.
