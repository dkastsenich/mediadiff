registry, a `Value` measurement read out of a `*.snap.json`, one comparison
semantic, baseline policy resolution, a JSON report, and a real exit code — with
nothing stubbed that cannot later be filled without an architectural change.

the layering is wrong, it is wrong after one commit instead of after ten.

byte-deterministic, and returns the contract exit code.

against. Write no comparison logic, no serializer, no report renderer and no CLI

Registry generator (D-01, D-05). Create `tools/gen_registry.py`, a Python 3
script that reads `src/core/checks.def` with the standard-library `tomllib`
module and writes three files into the directory given by `--out-dir`. Guard the
interpreter floor: `sys.version_info >= (3, 11)` or exit non-zero with a message
naming the required version, since `tomllib` landed in 3.11. Arguments:
`--checks`, `--docs-dir`, `--out-dir`. `checks.def` is TOML-syntax despite the
`.def` name mandated by doc 01 section 2; record that in a header comment in the
file. Each entry is an `[[check]]` array-of-tables record with keys `id`,
`group`, `semantic`, `unit`, `value_kind`, `severity`, `tolerance` (optional),
`volatile` (optional bool), `requires_pass` (optional bool). Seed exactly the
three IDs approved in Task 1: `meta.tool_version`, `meta.missing_candidate`,
`meta.extra_candidate` — the latter two carry `semantic = "presence"` and are
registered but not exercised until plan 02-11. Generated outputs:
`check_id.h` (an `enum class CheckId : std::uint32_t` with one enumerator per
check named by replacing `.` with `_`, terminated by `kCount`, plus a
`constexpr std::string_view kCheckIdStrings[]` in the same order),
`check_registry.cpp` (the `CheckDef` table plus a
`const CheckRegistry& builtin_registry()` accessor), and `check_explain.cpp`
(each `docs/checks/<id>.md` body embedded as a raw string literal keyed by
`CheckId`). Validate the ID grammar `[a-z0-9_]+(\.[a-z0-9_]+)*` and exit non-zero
naming the offending ID when it does not match. Exit non-zero when a registered
ID has no readable, non-empty `docs/checks/<id>.md` — that is the mechanism that
makes ENG-01/DOC-01 a build failure rather than review discipline (D-02); report
every missing ID sorted, not only the first. Write each output to a sibling
temporary file and `os.replace` it into position so a concurrent build never
observes a half-written header.

Header compilation gate. A header nothing includes is a header nothing
type-checks, and this task's output is almost entirely headers — so declare the
five new `src/core/*.h` files on `libmediadiff` via
`target_sources(libmediadiff PUBLIC FILE_SET HEADERS BASE_DIRS ${CMAKE_SOURCE_DIR}/src FILES ...)`
and set `VERIFY_INTERFACE_HEADER_SETS` to `ON` on the target. That makes CMake
generate a `libmediadiff_verify_interface_header_sets` target (reachable via the
aggregate `all_verify_interface_header_sets`) which compiles each header
standalone under the same warnings-as-errors flags, so a missing include or a
typo in a struct nobody instantiates yet is caught in this task rather than
surfacing as a confusing error inside Task 3. This mechanism requires CMake 3.24
and the project floor is 3.25. Tasks 3 and 4 extend the same file set.

Core types. `src/core/error.h`: `enum class ErrorKind { usage, input_open, input_unsupported, decode, internal }`
and `struct Error { ErrorKind kind; std::string message; }`. The `message` field
is required now because CLI-10 must name an expected unit later. `src/core/rational.h`:
`struct Rational { std::int64_t num; std::int64_t den; }` and
`struct Ticks { std::int64_t value; Rational tb; }`, with an overflow-checked

`double` — use `__builtin_mul_overflow` on GCC/Clang and `_mul128` from
`<intrin.h>` on MSVC, behind one `#if defined(_MSC_VER)`. No libav header is
included anywhere under `src/core/` (D-07).
`src/core/value.h`: `using Value = std::variant<Absent, std::int64_t, RationalValue, double, std::string, StringSet, Histogram, SpanList, HashChain>`

## Sequencing rationale

Phase 2 runs eleven plans in eleven waves, one plan per wave, with no two plans
executing concurrently. That is deliberate, and it is recorded here rather than
only in the planner's return message so that anyone reading the plans can see why
no parallelism was attempted.

**Every plan writes the shared CMake source lists.** Each plan appends its new
`.cpp` files to `add_library(libmediadiff STATIC ...)` in `CMakeLists.txt`, its
new unit tests to `add_executable(mediadiff_unit_tests ...)` in
`tests/unit/CMakeLists.txt`, and its new integration tests to
`add_executable(mediadiff_integration_tests ...)` in
`tests/integration/CMakeLists.txt`. These are concurrent **appends to the same
source lists**, not merely concurrent reads — two plans running in the same wave
would each rewrite the same list region from a stale base and one set of sources
would silently vanish from the build. Consequently no two plans in this phase have
disjoint `files_modified`, and the wave assignment rule (same-wave plans must have
zero `files_modified` overlap) forces one plan per wave on its own.

**The nearest-looking parallel candidates overlap in real source files too**, so
even a hypothetical fix to the CMake contention would not free them:

| Candidate pair | Overlapping files |
|---|---|
| 02-05 ∩ 02-06 | `src/core/policy.h`, `src/core/policy.cpp` — 02-05 writes layers 1-2 of the precedence merge, 02-06 extends the same `resolve_policy` to layers 3-4 |
| 02-04 ∩ 02-05 | `src/compare/engine.cpp` — 02-04 adds the semantic dispatch arms, 02-05 adds the severity/volatile resolution the dispatch consults |

**The layering is a genuine dependency chain regardless.** The phase builds
model -> registry -> semantics -> policy -> snapshot -> reports -> CLI -> `dir`,
and each stage consumes types and functions the previous stage introduces: the
semantics need `CheckDef` and `Value`; policy resolution needs the semantics'
`Tolerance`; the report model needs resolved `Finding`s; the CLI needs the
renderers; `dir` needs the whole single-file path working. Removing the CMake
contention entirely would therefore not unlock a single additional parallel pair —
it removes no parallelism that existed. The serialization costs nothing beyond
what the dependency graph already imposed.
