Write a new bash lint, `scripts/lint_dead_code_after_fail.sh`, whose single charter is: **within any test source, no statement may follow a Catch2 unconditional-failure statement before the enclosing block closes.** That is the exact shape MSVC proves unreachable and rejects under `/W4 /WX`, and it is copy-paste-prone, which is why the user's own gap diagnosis calls for a scan rather than a one-file fix.

Scan target: the `tests` directory, restricted to `*.cpp` and `*.h`. Follow `lint_check_id_strings.sh`'s guard exactly — if `tests` does not exist, or if the file enumeration yields zero files, print a diagnostic to stderr and exit 1. A gate that scans nothing is not a gate that found nothing.

Matcher, expressed as a three-state line scan (awk is the natural fit and is present on `ubuntu-24.04`, which is the only runner the `lint` job uses):

- **State 0 — searching.** Reset to this at the start of every file. A line whose content matches the Catch2 unconditional-failure macro used as a call — the macro name preceded by a non-identifier character or start-of-line, followed by optional whitespace and an opening parenthesis — arms the scanner into state 1. Nothing else does.
- **State 1 — consuming the failure statement.** Advance until a line whose trimmed content ends with a closing parenthesis followed by a semicolon. This is what makes the scanner correct for a failure macro whose arguments span several lines, which a naive next-line check would miss entirely. That terminating line moves the scanner to state 2.
- **State 2 — judging what follows.** Skip blank lines, lines whose trimmed content begins with a `//` comment, and preprocessor lines beginning with `#`. The first surviving line decides: if its trimmed content begins with a closing brace, this is a correctly-shaped failure (it is the last statement of its block) and the scanner returns to state 0 silently. Anything else is a violation — print `file:line` and the offending trimmed line, record that a violation occurred, and return to state 0 so the rest of the file is still scanned.

Exit 1 listing every violation if any were found; otherwise print a single clean line naming what was scanned and exit 0.

**Self-test control clause, run before the real scan on every invocation.** Materialise a synthetic known-bad fixture in a temporary file — a function containing the failure macro with its argument split across two lines, then a `static` declaration, then a return, then the closing brace — run the identical matcher against it, and exit 1 with a distinct diagnostic if the matcher does NOT flag it. Clean up the temporary file on exit with a trap. This is the same discipline `02-13-PLAN.md` used as an inline control clause, promoted into the gate itself: without it, a matcher that silently stops matching (a regex typo, an awk version difference) reports "clean" forever and the gate becomes decorative. `02-13`'s own root cause was a verification that had only ever been run one way.

Document, in a "Known limitation (stated deliberately, not hidden)" paragraph matching the two existing lints' register: this is a line-based scan, not a C++ tokenizer; a `/* ... */` block comment appearing immediately after a failure statement will be misread as a statement and produce a false positive; and a failure statement written inside a macro of the project's own would not be recognised. State that the correct response to a genuine false positive is a per-line allow-marker convention, not a rewrite into a tokenizer — the same escape valve `lint_eng16.sh` documents.

Record in the header comment what this gate is defending and why the pattern is worth a permanent scan: `mediadiff_apply_warnings()` puts `/W4 /WX` on all four first-party targets including both test executables, MSVC escalates unreachable code to a hard error, and as of this plan eighteen test translation units — the four unit TUs `test_dir_pairing.cpp`, `test_golden.cpp`, `test_process_spawn.cpp`, `test_worker_pool.cpp` and all fourteen integration TUs — have never been compiled by MSVC in any CI run, so the Windows leg is not a reliable detector for a shape this cheap to check on every push.
