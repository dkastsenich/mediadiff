## Where this plan departs from the gap records' grouping, and why

**`#95` is not part of `G-02-5`'s newline cause.** The gap groups it with the three golden failures under one root cause and treats its 2,500-byte delta as the strongest evidence for that grouping. The arithmetic is right and the attribution is not. `tests/unit/test_process_spawn.cpp:38` spawns `MEDIADIFF_PYTHON` — *Python*, not mediadiff — and lines 35-36 write through `sys.stdout.write` / `sys.stderr.write`, which on Windows are text-mode wrappers that expand each `chr(10)` to `\r\n`. 2,500 lines × 1 extra byte = the exact delta. The parent is innocent twice over: `tests/process_spawn.h:122-128` reads with raw `ReadFile` on Windows and `read()` on POSIX, neither of which translates. So `#95` says nothing whatsoever about mediadiff's own stdout mode, and it must not be closed by whatever closes the goldens. `02-17-PLAN.md` owns the goldens and the product's stdout; this plan owns only the Python fixture.

**`#36`'s boundary is the test's path construction, not `/utf-8` and not `std::filesystem` generally.** `G-02-6` asks first whether `/utf-8` is actually applied to the test targets. It is: `mediadiff_apply_warnings` sets `/W4 /WX /utf-8` at `CMakeLists.txt:227` and is called for both test executables. And it would not matter if it were absent — the literal at `test_dir_pairing.cpp:197` is `"r\xC3\xA9sum\xC3\xA9.snap.json"`, byte-explicit escapes that no source-charset flag can change. So the gap's second bullet applies: the defect is at the narrow/wide boundary. Specifically, `test_dir_pairing.cpp:198-199` writes `baseline / non_ascii_name` where `non_ascii_name` is a `std::string`, which invokes `std::filesystem::path`'s narrow constructor. On MSVC that decodes through the CRT's active code page, not UTF-8 — so the bytes `C3 A9` become the two CP1252 characters `Ã©` and the file is created on disk as `rÃ©sumÃ©.snap.json`. `src/cli/dir_pairing.cpp` then reads it back **correctly**, converting the wide name to UTF-8 at CP_UTF8, which re-encodes those two characters as `C3 83 C2 A9` — the four bytes the log renders as `rÃ©sumÃ©`. The product is right; the fixture put the wrong file on disk. That is also why the mojibake appears on the left of the expansion and the intact UTF-8 on the right.
