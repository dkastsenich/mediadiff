<objective>
Build the shared report model every renderer consumes, then the three file-bound
report formats: schema-validated JSON, Markdown inside a real byte budget with an
honest overflow fold, and JUnit that a CI server displays without configuration.

Purpose: four renderers independently re-deriving "group in fixed order, filter
non-pass, look up the accept/tune/silence triple" is the read-side version of the
problem D-08 solved on the write side — one of them will drift, and the drift
will look like a false positive to whoever reads that format.
Output: one `ReportModel`, three renderers, a shipped JSON schema validated in
the test suite, and `--json` / `--report kind=path` wired end to end.
</objective>

finding span. The document keys are inserted in a fixed sequence: `schema_version`,
`tool_version`, `profile`, `summary`, `diagnostics`, `findings`. Every finding

present, `null` when none) and `evidence`. Under `-v` each finding additionally

glob plus its file position, or the argv text plus its index) and `value` (the
severity that layer wrote), emitted in chain order, which is resolution order.

is the resolved severity by construction. This is the machine-readable mirror of
the text chain plan 02-06 renders for `list-checks --effective -v` — same three

rendered through `value_to_json` and the document through `serialize_document`,
so the report and the snapshot share one formatter and cannot diverge on floats.
No timing field appears anywhere in the document, which is what makes the
byte-identity guarantee unconditional rather than qualified.

enumerations, the closed `skip_reason` enumeration including `null`, and
`additionalProperties: false` at the finding level so a renderer cannot quietly
add an undocumented key.

Implement `src/report/markdown.{h,cpp}`:
`std::string render_markdown(const ReportModel&, const CheckRegistry&)`.

Layout: a summary table with one row per status and explicit counts, followed by
one `<details>` block per group in the model's group order, each containing that
group's findings as a table. A group with exactly one finding still gets its own
`<details>` block, and a run with zero findings still emits the summary table with
explicit zeros — an empty document would read as "the tool did not run" rather
than "nothing changed".

The budget is a named constant `kMarkdownBudgetBytes = 60000`, counted in UTF-8
bytes, with a comment recording that GitHub's comment limit is 65,536 characters
and that this figure carries deliberate headroom because multi-byte content
inflates bytes relative to characters. Render into a buffer and measure as bytes;
when the rendered body is at or under the budget it is emitted unchanged, and
when it is over by even one byte the fold engages.

The fold drops whole findings from the end of the lowest-severity group first,
never partial rows, and appends a single line naming the exact number of findings
withheld and directing the reader to the JSON artifact. Two rules make the fold
honest, and they are the prohibition recorded in this plan's `must_haves`: the
count in that line is the real number withheld, and gating findings (`fail`, and
`warn` under `--strict`) are dropped only after every non-gating finding has
already been dropped, so the formats never disagree about whether the build
should block. When nothing was withheld the line is absent entirely rather than
rendered with a zero. If the summary table alone would exceed the budget — which
requires a pathological group count — truncate on a UTF-8 character boundary,
never mid-code-point, and still append the fold line.

`tests/unit/test_markdown_budget.cpp`, tag `[markdown]`: a zero-finding model
renders a summary table with zeros and no `<details>`; a one-finding group renders
a `<details>` block; a model rendering to exactly `kMarkdownBudgetBytes` is
emitted unchanged and carries no fold line; a model one byte over folds and the
fold line names the real withheld count; a model whose findings carry multi-byte
characters folds on a character boundary, asserted by validating the output is
well-formed UTF-8; an oversized model still contains every `fail` finding after
folding; and the golden Markdown for a fixed model matches through `check_golden`.

Implement `src/report/junit.{h,cpp}`:
`std::string render_junit(const ReportModel&, const CheckRegistry&)`.

One `<testsuite>` per group in the model's group order, one `<testcase>` per
gating-capable finding — those whose resolved severity is `warn` or `fail`. The
`classname` is the group name and the `name` is `<check.id>[<scope>]`, so two
findings for the same check at different scopes produce distinct names and a CI
server does not collapse them. A `fail` becomes a `<failure>` whose `message`
attribute is the finding message and whose body is the baseline-versus-candidate
detail; a `warn` becomes a `<failure>` when `--strict` is in effect and otherwise
a `<skipped>` carrying the same message, so what the exit code says and what the
CI UI shows agree. A `skipped` finding becomes a `<skipped>` element carrying its
machine-readable reason, never a passing testcase. Emit the `tests`, `failures`
and `skipped` attributes computed from the elements actually written. A run with
no gating-capable findings still emits a well-formed document declaring zero
tests. XML-escape every attribute value and every text body — a finding message
can contain a filename with an ampersand or an angle bracket, and an unescaped
one produces a document a CI server silently discards.

Wire the flags in `src/cli/options.{h,cpp}` and `src/cli/commands/compare.cpp`:
`--json` with an optional `=path` value writes JSON to that path or, when the
value is absent, to stdout; `--report kind=path` is repeatable and accepts the
kinds `md` and `junit`, parsed into an ordered list of `{kind, path}` pairs. An
unrecognised kind, a missing `=`, an empty path, or two `--report` flags naming
the same path is `ErrorKind::usage` (exit 64) naming the offending argument. Each
destination is opened through `fopen_utf8`, written and closed independently, so
three destinations mean three distinct file handles and no shared buffer. All
opening and writing happens in `src/cli/`; the renderers return strings and touch
no file (ENG-16).
