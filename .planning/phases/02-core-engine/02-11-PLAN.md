<objective>
Ship `dir` mode: pair a corpus by relative path in a deterministic order, report
unpaired files as findings rather than as prose, run the pairs through a
`--threads`-bounded pool whose completion order cannot affect the output, and roll
per-file results into corpus totals and a `files[]` JSON layer.

Purpose: `dir` is how a 240-file corpus gets diffed across an FFmpeg major
version. A report whose ordering shifts between runs cannot be diffed, and a
corpus report that cannot be diffed is the same as no report.
Output: `mediadiff dir a b --threads N --json` producing byte-identical output at
every thread count.
</objective>

Implement `src/cli/worker_pool.{h,cpp}` as a fixed-size pool over a
pre-sorted, index-addressed job list. Use plain `std::thread` with a mutex, a
condition variable and an atomic index counter — not `std::jthread` and not
`std::stop_token`, both of which are excluded for toolchain parity, and the
project's threading model needs no cooperative cancellation.

`class WorkerPool` takes a thread count in its constructor and exposes
`void run_indexed(std::size_t job_count, const std::function<void(std::size_t)>& job)`
which runs each index exactly once and returns only after all have completed. The
caller writes each result into `results[index]` of a vector pre-sized to
`job_count`, so nothing is appended in completion order and output ordering is
structurally decoupled from scheduling. A thread count of zero or one runs the
jobs on the calling thread with no thread created, so a single-threaded run has no
concurrency at all rather than a pool of one. Resolve the default thread count
from `[dir] threads` in `mediadiff.toml` when present, overridden by `--threads`,
defaulting to the hardware concurrency clamped to a documented maximum; a
`--threads` value of zero or a negative value is `ErrorKind::usage` (exit 64).

If a job throws — which library code must not do, but `std::filesystem` and the
standard library can — catch at the pool boundary, record the failure against that
index, and let the run complete so the corpus report still covers every other
file. No exception crosses back out of `run_indexed`.

In `src/cli/commands/dir.cpp`: load the config and resolve the policy once,
before the pool starts, and pass the resolved `Policy` to every job by const
reference. Apply the `[override."<glob-on-relative-path>"]` blocks per file by
resolving a per-file policy from the shared base — each job computes its own
`Policy` copy from the immutable base plus the overrides matching its relative
path, so no job mutates shared state. Add the `--content` and `--no-content`
flags as plumbing only: they set a pass-selection field on the per-file request
that the probe layer will consume in Phase 3, and `--content` currently produces a
diagnostic stating that the decode pass arrives with that phase. `--help` for
`dir` states the corpus-speed trade so the choice is documented where the user
makes it.

`tests/unit/test_worker_pool.cpp`, tag `[pool]`: `run_indexed` runs every index
