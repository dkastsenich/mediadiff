  <action>
Implement `src/core/tolerance.{h,cpp}` as a pure, file-I/O-free, CLI11-free
parser.

`struct Tolerance { Unit unit; std::int64_t num; std::int64_t den; bool is_relative; std::optional<std::int64_t> warn_num; };`
— the magnitude is stored as an exact rational so a value written `0.2ms/min`
never becomes a `double`. `is_relative` marks the percent form. `warn_num` carries
the optional second threshold when a check declares `{warn, fail}`.

`mediadiff::expected<Tolerance, Error> parse_tolerance(std::string_view raw, Unit expected_unit)`
accepts exactly the grammar in doc 01 section 3: a magnitude followed by one of
the suffixes `ms`, `%`, `frames`, `ms/min`, `LU`, `dB`, `samples`, `tick`,
`bytes`, or no suffix at all, and optionally prefixed by the plus-minus sign
U+00B1 or the two-character ASCII sequence `+-`. The magnitude is parsed from its
decimal text into an exact `num`/`den` pair by counting fractional digits — never
through a locale-sensitive C-library string-to-floating-point conversion — so
`0.2` becomes `2/10` rather than the nearest representable binary value.

Every rejection is `ErrorKind::usage` with a message that names the check's
expected unit, because CLI-10 requires the diagnostic to be actionable. Reject:
an empty or whitespace-only value; a magnitude with no digits; a suffix not in
the grammar; a suffix whose unit does not match `expected_unit`; a negative
magnitude; and any non-ASCII character other than the U+00B1 sign — in
particular a full-width digit or a Unicode minus sign is rejected rather than
normalised, so a value cannot silently become a different number.

Add a `Unit`-to-suffix table in `src/core/registry.h` (or a small function beside
it) so the message can render the expected unit as the same text a user would
type.

`tests/unit/test_tolerance.cpp`, tag `[tolerance]`, table-driven over: each valid
suffix; the plus-minus prefix in both spellings; an integer magnitude; a
fractional magnitude asserted to produce the exact rational rather than a
rounded one; the two-threshold form; and the rejection cases above, each asserted
to carry `ErrorKind::usage` and a message containing the expected unit's suffix
text. Assert explicitly that an empty value is rejected rather than parsed as
zero, and that a fractional magnitude round-trips exactly.
  </action>

  <action>
Implement one comparator per file, each matching the `Comparator` typedef and
each a pure function of its arguments — no file I/O, no standard-stream write,
no `exit()`.

Before dispatching, `compare_fingerprints` asserts that both measurements' held
variant alternative matches the registry's declared `value_kind`; a mismatch
produces a `Finding` with `Status::error` and a message naming the declared and
the observed kind (D-09). This runs for every semantic, so no comparator needs to
re-check it.

`tol.cpp` — pass when the absolute delta is less than or equal to the threshold,
comparison inclusive at the boundary. When the check's unit is a time unit, both
values are `RationalValue` and the comparison runs through `compare_ticks` after
rescaling both into a common timebase by integer cross-multiplication; no code
path in this file converts a tick count to `double`. When the tolerance is
relative, compare `|delta| * 100 * baseline_den` against `percent_num * |baseline|`
by integer multiplication rather than computing a ratio. When the check declares
two thresholds, a delta inside `warn` is `pass`, between `warn` and `fail` is
`warn`, and beyond `fail` is `fail`. Render the delta as a signed value plus, for
a relative tolerance, the percentage.

`set.cpp` — pass when the symmetric difference is empty after removing the
check's ignored elements. Both inputs are `StringSet`, which is ordered, so the
comparison is order-insensitive by construction; render added and removed
elements in sorted order so output does not depend on insertion order.

`presence.cpp` — pass when both sides are `Absent` or both are present; fail
otherwise. Do not compare the values themselves; doc 01 section 3 makes any value
comparison a separate `tol` check on the same extraction.

`hash.cpp` — before comparing digests, check the recorded preconditions carried
in the measurement's evidence: same decode-path class, same sampling state, same
normalisation. When any precondition differs, return `Status::skipped` with
`SkipReason::hash_incomparable` and a hint directing the user to a perceptual or
epsilon comparison. Never fabricate a pass and never fabricate a fail in that
case. When the preconditions match, compare `HashChain::algorithm` and
`HashChain::digest`; a differing digest is a fail whose message reports the
element count on each side, with first-divergence reporting deferred to Phase 7
where per-element digests exist.

`dist.cpp` — normalise both `Histogram` bin counts into proportions as exact
rationals over their respective totals, take the maximum absolute difference
across bins present in either side (a bin absent on one side counts as zero
there), and compare that maximum against the tolerance. Report the worst bin by
name. Two empty histograms pass.

`span.cpp` — interval algebra over two `SpanList`s. A span present in the
candidate that does not overlap any baseline span is an *introduced* span and
gates; a baseline span absent from the candidate is reported at `info` and does
not gate. Merge adjacent spans separated by no more than one frame before
comparing, using the check's timebase for the gap, and sort output spans by start
time so the rendering is stable.

Update `comparator_for` in `semantics.h`/`engine.cpp` to return the real
comparator for all seven `Semantic` values, written as a `switch` with no
`default:` arm so an added semantic is a compile error.
  </action>
