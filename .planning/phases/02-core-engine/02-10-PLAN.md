Split `src/cli/exit_code.h` into a header plus `exit_code.cpp`, and add the
second half of the contract alongside the existing `ErrorKind` mapping:
`int exit_code_for_findings(const Summary&, bool strict)` returning
`kExitFail` when any gating finding is `fail`, `kExitWarnStrict` when the worst is
`warn` and `strict` is set, and `kExitClean` otherwise. Both functions are
`switch`-based over closed enumerations with no `default:` arm, so a new
`ErrorKind` or `Severity` is a compile error rather than a silent fallthrough to
the wrong code.

Partial results on 66 (CLI-07). When the compare path returns an `Error` whose
kind is `decode`, or when a fingerprint carries `partial == true`, the command
still builds a `ReportModel` from whatever findings were computed, still writes
every requested report destination, and only then returns 66. The JSON document
carries the partial marker in its envelope and a diagnostics entry naming what
failed, so a CI job can see what was measured before the failure — partial truth
beats silence, and CI can distinguish the two. No probe layer exists until Phase
3, so the `decode` path is reached in tests by a snapshot whose envelope declares
`partial: true` together with a diagnostics entry; the plumbing is what this task
delivers and proves.

Audit every `return` from a CLI callback so no path returns a bare integer
literal that is not one of the seven named constants, and no path returns
`app.exit(e)`'s value unmodified.

`CheckRegistry::find` and, failing that, through `resolve_alias`; an alias hit

is where ENG-03's warning becomes user-visible. An unresolvable ID is
