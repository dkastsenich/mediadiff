reintroduce a second float formatter. Keep the existing comment at the

compile-time smoke assertion — a `static_assert`-adjacent runtime check in the
serializer's own unit test — that the floating-point `std::to_chars` overload is
available, so a future toolchain change surfaces as a named test failure rather
than a cryptic build error.

Serialize each `Value` alternative exactly once, in `value_to_json`'s single
`std::visit`: `Absent` as a JSON null tagged with its kind so it reads back as
`Absent` and never as a missing key; `std::int64_t` as an integer;
`RationalValue` as `{"num", "den", "tb": {"num", "den"}, "ms"}` where `ms` is the

`{"start", "end"}` objects sorted by start; `HashChain` as
`{"algorithm", "digest", "element_count"}`. An empty `StringSet`, `SpanList` or
`Histogram` writes an empty array — distinct from `Absent`'s null — so the two
cannot be confused on read-back.

`value_from_json` reverses each arm and returns an `Error` when the encoded shape
does not match the registry's declared `ValueKind`. It never coerces: an integer
where a string is declared is `ErrorKind::input_unsupported`, not a stringified

The safe-write gate (SNAP-07). Before any byte is written, if the target path
exists, determine whether it is tracked by git by invoking
`git ls-files --error-unmatch -- <path>` in the target's directory and reading
the exit status. When the file exists and is tracked and `--force` was not given,
refuse with `ErrorKind::usage` (exit 64) and a message naming `--force`; leave
the existing file byte-identical. When the file exists but is untracked, proceed.

untracked and proceed, but say so in the message on the refusal path so the
behaviour is never silently permissive without explanation. The gate keys on
tracked-ness rather than on `CI=true` alone because a tracked baseline is what a
misinvoked job would launder a regression into; also refuse when `CI=true` is set
and the target exists, tracked or not, since an automated job overwriting any
existing baseline without `--force` is the failure mode this requirement names. A
zero-byte existing file is protected exactly like a non-empty one.
