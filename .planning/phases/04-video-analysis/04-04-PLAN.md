<objective>
The HDR half of the corpus: real `mdcv` and `clli` boxes around ordinary `mpeg4` encodes, arranged
so every HDR check has a pair that differs in exactly its own dimension, plus the three coherence
fixtures D-10's new check needs.

Purpose: `VIDEO-09` names `codecpar->coded_side_data` as the first extraction source and there is
no decode pass in this phase, so stream-level boxes are the only source that can exist. D-09
establishes that they can be written around a plain LGPL encode; this plan turns that finding into
the fixture set plans 04-11 and 04-12 consume.
Output: roughly ten HDR fixtures, each verified by reading its metadata back out, and a
regenerated corpus digest.
</objective>

**A1 — The Matroska path is unverified.** Research Open Question 2 and Assumption A1 are both open:
the input-side attachment mechanism is container-independent, but whether `matroskaenc.c` and
`matroskadec.c` write and read the equivalent elements from the same side-data fields was never
tested. This plan targets MP4 for every HDR fixture, which IS verified — twice, by the researcher
and again by the orchestrator, down to the box offsets. Task 2 runs the five-minute Matroska check
and RECORDS the answer for a future phase; nothing in this phase depends on the answer.

**A2 — Chromaticity comparison granularity.** The roster compares the eight chromaticities `exact`
after quantisation to the 0.0002 grid, because the values round-trip as exact rationals (the
orchestrator observed `red_x=34000/50000` surviving intact). The `video_hdr_prim_b.mp4` fixture
must therefore differ by MORE than one grid step, or the trigger will not fire. Choose primaries
that differ substantially — DCI-P3 versus BT.2020 — rather than by a few raw units.

**A3 — Spec-less edge probe.** Two of the 17 unresolved probe items are authored into this plan's
`truths` and its fixture set: **VIDEO-09-E1** (stream-level absent on a codec that could carry
frame-level yields `requires_decode`, versus a codec that could not, which yields a plain absence —
so the corpus must contain both cases) and **VIDEO-10-E1** (the coherence guard must fire when both
files SHARE the incoherence, which is why `video_hdr_sdr_mdcv.mp4` needs a byte-identical copy
rather than only an opposite-valued partner).
</flagged_assumptions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a recipe's declared HDR metadata -> the produced file's actual boxes | An accepted CLI option is not evidence a box was written; a fixture with no box compares absent-to-absent and looks clean. |
| the pinned generator's muxer behaviour -> the fixture corpus | Whether `mdcv`/`clli` reach the file at all is a property of the muxer, not of the command line. |
| two independently-varied extractions -> one coherence value | The coherence check reads MDCV presence and the transfer characteristic; a fixture that varies both at once cannot isolate either. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-15 | Tampering | an HDR fixture with no `mdcv`/`clli` box that still "passes" | high | mitigate | Every HDR fixture's produced file is byte-searched for its expected boxes and read back for its expected values before it is committed; the acceptance criteria assert exact box counts, and the read-back tables are recorded in the SUMMARY. |
| T-4-16 | Tampering | a coherence fixture whose transfer silently became `unspecified` | high | mitigate | Every coherence fixture's `colr` box transfer field is parsed from the raw bytes and asserted to the expected numeric value, not inferred from the `setparams` argument. |
| T-4-17 | Spoofing | an HDR recipe that would need a GPL encoder | high | mitigate | D-09's codec-independent input-side options with a plain `mpeg4` encode; an acceptance criterion greps the generator for external-encoder names. This is what keeps the Windows `-lgpl` leg able to produce the corpus. |
| T-4-18 | Repudiation | an unanswered Open Question carried silently into a later phase | low | mitigate | The Matroska round-trip is tested once and its answer recorded in the SUMMARY whichever way it goes, so a later phase inherits evidence rather than an assumption. |
| T-4-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed by this plan; no manifest changes. |
</threat_model>
