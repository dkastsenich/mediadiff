variable-length per-AU sequence would make the per-AU footprint unbounded, which is incompatible
with D-01's accounted byte budget. This plan stores the information the classifier actually
consumes in fixed width: a 64-bit set of NAL types observed in the access unit plus the leading
VCL NAL type. `04-RESEARCH.md`'s Pitfall 2 states the requirement as "the raw NAL type (or at
minimum an IDR-vs-other-IRAP boolean derived from it)", which this satisfies with room to spare.
If a later phase needs true ordering within an AU, that is an additive field, not a reshape.

**A3 — `video.gop.length` on MPEG-4 Part 2.** `key_frame` for `mpeg4` comes from libav's
`mpeg4video` parser, not from a NAL walk (D-04's own point: real MPEG-2/MPEG-4 fixtures are the
only thing exercising the parser-outputs-only branch). This plan's fixture pair was generated and
counted during planning against the pinned `9.0.1` generator: `-g 48` over a 4-second 25 fps
`testsrc2` produced 3 keyframes, `-g 96` produced 2 — median distances 48 versus 96, a 100 %
delta against a 10 % tolerance. If the parser's `key_frame` disagrees with the packet flag on this
codec, Task 3's assertion fails loudly rather than silently degrading.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| attacker-controlled packet payload bytes -> the Annex-B start-code walk | Every byte of `AVPacket::data` is chosen by the file; the walk searches it for start codes and indexes past them. |
| attacker-controlled access-unit cardinality -> the per-AU record store | A file with millions of tiny access units grows a second array beside `PacketRecord` inside the same process. |
| attacker-controlled codec id -> `av_parser_init` / `avcodec_alloc_context3` | A stream can name any codec, including one with no parser or an allocation-heavy context. |
| `ParserScanResult::partial` -> the decision to answer or refuse | The truncation flag is the only thing between a truncated parse and a confidently wrong GOP length. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-01 | Denial of Service | per-access-unit record growth in `ParserScanResult` | high | mitigate | Every `AccessUnitRecord` append is accounted against the SAME `accounted_bytes` total and the SAME `PacketScanLimits::max_bytes` ceiling `PacketRecord` already uses, via `detail::checked_add`; exhaustion sets `partial` and stops appending. No second, independent budget is introduced. |
| T-4-02 | Denial of Service | `AVCodecParserContext` / `AVCodecContext` leak across a `dir`-mode corpus run | medium | mitigate | One RAII holder per stream mirroring `ScratchPacket`'s discipline; `av_parser_close` and `avcodec_free_context` run on every exit path including the early-return error paths. |
| T-4-03 | Tampering | Annex-B start-code search reading past a truncated packet | high | mitigate | Every index into the packet buffer is bounds-checked against the packet's own declared `size` before dereference; a start code with insufficient trailing bytes is dropped rather than read. Test 6 is the regression pin. |
| T-4-04 | Denial of Service | a crafted packet of millions of three-byte start codes | high | mitigate | The walk stops after `kMaxNalsPerAccessUnit`, a named constant with no bare literal at any use site; Test 7 drives the bound directly. |
| T-4-05 | Spoofing | a stream naming a codec whose parser refuses to initialise | medium | mitigate | `av_parser_init` returning null sets `has_parser = false` for that stream and records nothing; the dependent check emits `skipped:no_parser` (VIDEO-12) rather than propagating a raw libav error or reporting from an uninitialised context. |
| T-4-06 | Repudiation | a `partial_scan` skip a user cannot act on | medium | mitigate | The skip's evidence names the resolved per-file byte cap and the access-unit count reached, so the user knows to raise `--probe-memory-budget-mb` or lower `--threads`. |
| T-4-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed by this plan. `04-RESEARCH.md`'s Package Legitimacy Audit records that this phase introduces no new external dependency; the Python helper this phase adds later is stdlib-only. |
