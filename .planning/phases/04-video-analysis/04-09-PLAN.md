rather than from a boolean that cannot tell them apart, reference-frame count, and the I/P/B
distribution — with an explicit, documented degradation for codecs the parser cannot read.

distinguishing an open GOP from a closed one is invisible to the obvious API. VIDEO-12 makes the
degradation path explicit rather than leaving a check silently absent.

DOC-03 pairs, and a hand-verified classification table.

<flagged_assumptions>
**A1 — `video.gop.refs` has no public libav accessor.** `AVCodecParameters` carries no
reference-frame count and `AVCodecParserContext` does not expose one either; the H.264 parser reads
`sps->ref_frame_count` internally and never publishes it. Doc 03 §2 words the check as "`refs` from
SPS via parser where available, else `codecpar` evidence-only". Task 2 therefore reads the SPS's
own reference-frame field during the NAL walk, using the bit reader plan 04-05 already had to build
for the writer side — the reader and the writer are symmetric and the writer's fixtures are the
reader's test vectors. If execution finds a public accessor that already carries the value, prefer
it and record the finding. For codecs with no SPS concept at all (`mpeg4`, `mpeg2video`) the check
emits an explicit skip naming the codec, not a fabricated zero.

**A2 — The H.264 parser's keyframe heuristic will show up in the refs fixtures.** Research Priority
Finding 3 records that `key_frame` is set for a non-IDR I-slice when `ref_frame_count <= 1` and
`ref_count[0] <= 1`. Plan 04-05's `video_h264_refs1.h264` declares one reference frame, so its
non-IDR I-slices may report as keyframes while `video_h264_refs4.h264`'s do not. That is a real
behaviour of the parser this project links, not a fixture defect. Assert what the parser actually
does and record it; do not "correct" it.

**A3 — Spec-less edge probe.** Three of the 17 unresolved probe items are authored into this
plan's `truths`: **VIDEO-05-E1** (fewer than two keyframes yields insufficient-data, never a zero),
**VIDEO-05-E2** (`CRA_NUT` classifies open despite setting `key_frame`) and **VIDEO-12-E1** (the
no-parser path still reports a degraded frame-type split from packet flags, with the degradation
recorded in evidence).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| attacker-controlled NAL payload bytes -> the SPS bit reader | An SPS is a bit-packed structure whose own declared field values drive how many further bits are read. |
| attacker-controlled access-unit cardinality -> the classification walk | A file can declare millions of access units, each with a NAL type mask to inspect. |
| attacker-controlled picture-type distribution -> the histogram | A crafted stream can produce an enormous number of distinct picture-type bins. |
| either scan's `partial` flag -> the decision to classify or refuse | A GOP cadence from a truncated parse is a confidently wrong number. |
