<flagged_assumptions>
**A1 — The chromaticity tolerance is expressed as quantisation, not as a comparator change.** Doc 03
§4 specifies a 0.0002 absolute tolerance on chromaticities. The registry carries one semantic per
check and `tol` operates on a single scalar, so eight chromaticities cannot be compared under a
tolerance by the existing comparator. The roster's answer, approved at plan 04-01's checkpoint, is
to quantise each chromaticity rational to the 0.0002 grid with integer arithmetic and compare the
resulting canonical string `exact`. That yields exactly the specified tolerance semantics with no
comparator change and no floating point. The rounding rule at a grid midpoint must be fixed and
documented, because a value landing exactly on a boundary must round the same way on every platform
and in every run.

**A2 — MaxFALL gets its own id rather than riding as evidence.** Doc 03 §4 names both MaxCLL and
MaxFALL under one row. A single check can compare only one scalar under a tolerance, and folding
MaxFALL into evidence would mean a pipeline that halved MaxFALL alone reports `pass` — a false
negative in the class this project treats as P0. Both were approved at the roster gate.

**A3 — Spec-less edge probe.** One of the 17 unresolved probe items is authored into this plan's
`truths`: **VIDEO-09-E1** — absent-because-the-codec-cannot-carry-it must be distinguishable from
absent-because-we-did-not-decode. That distinction is the entire observable difference between an
ordinary `presence` comparison and a `requires_decode` skip.
</flagged_assumptions>

## Trust Boundaries

| Boundary | Description |
