<flagged_assumptions>
**A1 — Exp-Golomb bit layouts are the one genuinely unverified area in this phase.** Research
Assumption **A2** and Open Question **3** are both open: the research pass established WHICH SPS/PPS
fields the parsers consume and in what order, by reading `h264_parser.c` and `hevc/parser.c`
directly, but did not derive the exact bit widths of a minimal valid SPS/PPS from spec text. The
recommended mitigation is built into Task 1 as its first move: construct one candidate, run it
through the real linked `av_parser_parse2`, and iterate against that oracle before writing the
full generator. A malformed SPS does not crash — it silently fails to populate `pict_type`, which
is why the acceptance criteria assert on parsed OUTPUT, never on the bytes.

**A2 — `mediadiff` opens raw Annex-B elementary streams.** Verified during planning against the
built binary: a raw `.h264` file reports `container.format` of `h264` with one video stream, so
these fixtures need no MP4 muxing and no `avcC`/`hvcC` extradata construction. The linked FFmpeg
is configured with no demuxer or parser exclusions (confirmed from the vcpkg build's own configure
line), so the raw `h264`/`hevc` demuxers and both parsers are present.

**A3 — The `pasp` patch is a byte edit over an already-generated file.** Producing a
container-versus-bitstream SAR divergence is not expressible as a single encoder invocation: one
`-vf setsar` sets both. Patching the `pasp` box of a copy leaves the bitstream's own VOL header
untouched, which is exactly the divergence VIDEO-04 describes. If the resulting file's
`AVStream::sample_aspect_ratio` and `codecpar->sample_aspect_ratio` do not in fact diverge on
read-back, Task 2's own verify fails loudly and plan 04-07's VIDEO-04 conflict arm has no input —
report that rather than shipping a fixture that does not do what its name says.

**A4 — Spec-less edge probe.** One of the 17 unresolved probe items is authored into this plan's
`truths`: **PROBE-03-E1** — a parser that records nothing must be distinguishable from a parser
that failed. Every stream this writer produces targets a codec whose parser this phase depends on,
so "recorded nothing" here is a defect, not a degradation; the degradation case has its own
fixture (`video_noparser.mkv`, plan 04-02).
</flagged_assumptions>
