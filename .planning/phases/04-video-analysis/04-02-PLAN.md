<flagged_assumptions>
**A1 — `mjpeg` and `ffv1` on the Windows `-lgpl` pinned build.** Research assumption **A3** is
open: `mjpeg` was confirmed only on the Linux pinned binary (by the researcher and again by the
orchestrator). `ffv1` is proposed here as the no-parser codec for VIDEO-12 and has been confirmed
on no pinned build at all. Both are native FFmpeg codecs with no external library dependency, so
absence would be surprising — but "surprising" is not "verified". Task 1 makes the assertion
mechanical on every leg, so if either is missing the failure is loud, named, and lands at
`install_pinned_ffmpeg.sh` time rather than as an inexplicable missing fixture.

**A2 — `ffv1` genuinely has no libav parser.** Task 2 verifies this empirically against the
LINKED FFmpeg (not the generator) before committing the fixture, because VIDEO-12's whole point is
that `av_parser_init` returns null for the chosen codec. If `ffv1` turns out to have a parser, the
task's own verify fails and the alternate candidate is `prores` (also native, also LGPL) — the
decision criterion is the empirical `av_parser_init` result, never a recollection of which codecs
have parsers.

**A3 — mixed-interlace construction.** `video_ilace_mixed.mp4` concatenates an interlaced segment
and a progressive one. `codecpar->field_order` may well report a single value for the whole
stream; that is not a problem but the point — VIDEO-06 requires the DECLARED field order to be
cross-checked against PER-FRAME parser flags, and a stream whose declaration disagrees with its
own frames is exactly the fixture that proves the cross-check runs.

**A4 — Spec-less edge probe.** Four of the 17 unresolved probe items are authored into this
plan's `truths` and into the fixture set it produces: **VIDEO-03-E2** (all five `yuvj*` formats
fold, only 420 is fixture-exercised), **VIDEO-07-E1** (`chroma_loc` unspecified versus left is a
real difference, which is why a chroma pair exists at all), **VIDEO-08-E1** (both directions to
and from `unspecified` need fixtures, which is why `video_color_unspec.mp4` is a third file rather
than a mutation of one), and **VIDEO-12-E1** (a no-parser codec still has packet keyframe flags,
which is why the `ffv1` fixture is a real encode rather than a truncated file).
</flagged_assumptions>
