<flagged_assumptions>
**A1 — The epsilon value is a judgment call with permanent consequences.** D-07 fixes the SHAPE
(integer ticks, named constant, no percentage of a mean) and leaves the VALUE to the planner. The
proposal is zero ticks — exact equality against the mode interval — with the CFR threshold
expressed instead as the proportion of intervals that must match, matching doc 04's own "CFR
classified as at least 99.5 % of intervals equal to the mode interval". A non-zero tick epsilon
would need a defensible derivation from a real timebase, and none exists; a proportion threshold
is the parameter doc 04 already specifies. If execution finds real fixtures where an exact-tick
comparison misclassifies genuinely-CFR content, raise it rather than widening silently — a widened
epsilon is a compared class entering committed snapshots.

**A2 — The second consumer does not exist yet.** D-05 rates this `costly` precisely because Phase
5's timeline work is planned against this function being available and stable. Read
`claude_docs/04-timeline-analysis.md` before fixing the signature, and shape the return type
around what BOTH consumers need — mode interval, the axis used, the matching proportion, the
sample count — rather than around what `video.frame_rate.measured` alone needs today.

**A3 — Spec-less edge probe.** Two of the 17 unresolved probe items are authored into this plan's
`truths`: **VIDEO-01-E1** — an unset sample aspect ratio must be distinguishable in evidence from
an explicitly declared 1:1, even though the two compare identically (doc 03 §2 words it as
"0/1 treated as 1:1 with `unset` evidence") — and **VIDEO-04-E1** — the conflict check must report
the agreeing state rather than manufacturing a note, so it does not fire on every well-formed file.
</flagged_assumptions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| attacker-controlled PTS/DTS values -> interval arithmetic | Every timestamp is an int64 the file chose; the derivation subtracts, counts and compares them. |
| attacker-controlled timebase -> the rate expression | A timebase with a zero or negative denominator would be a division by zero in the rate derivation. |
| attacker-controlled interval diversity -> the mode-selection tally | A stream of millions of distinct interval values grows a tally the derivation walks. |
| attacker-controlled width/height/SAR -> the DAR derivation | A zero or enormous dimension would overflow or divide by zero in the ratio. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-28 | Denial of Service | the rate expression dividing by a crafted timebase | high | mitigate | `detail::checked_div` rejects a zero divisor before the division executes; a timebase whose denominator is zero or negative yields `skipped:insufficient_data`. An unguarded divide by zero terminates the process, which for a CI gate is a crash rather than a verdict. |
| T-4-29 | Tampering | interval subtraction and the rate cross-multiplication overflowing | high | mitigate | `checked_sub` and `checked_mul` at every step; an overflow collapses to insufficient-data rather than a wrapped interval that would report a plausible but wrong rate. |
