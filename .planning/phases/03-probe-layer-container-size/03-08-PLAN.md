<assumption_delta_decision>
**Detector fired: a real singular-to-plural transition in this phase.**

Prior assumption (Phases 1-2): every fingerprint describes ONE program's worth of media, and
`Scope{Kind::program, index}` — which shipped in Phase 2's `core/model.h` — has never been
constructed by any production code. `index`'s meaning for `Kind::program` was therefore
undefined in practice.

Transition: CONT-08 makes multi-program TS real. One file now yields several program-scoped
measurements per check, and two files must pair them.

**Decision: `promote`** — `Scope::index` for `Kind::program` is defined, from this plan onward,
to carry the PSI `program_number` (the value in the PAT, read via `AVProgram::program_num`),
NOT the `AVFormatContext::programs[]` array position.

Rationale: `compare_fingerprints` pairs by `(check_index, scope)`. Array-position indexing pairs
position 0 with position 0, so two files declaring the same two programs in different order
would compare program A against program B and report a plausible-looking difference that is
entirely an artifact of declaration order. A false positive of that kind is P0 in this project.
Promoting the field's meaning costs no schema change (the field already exists and is already an
`int`), requires no migration (no shipped snapshot contains a program-scoped measurement), and is
asserted by Task 3's behaviors 1, 2 and 5.

A second, smaller transition — one container format becoming three families under one
`container.*` group — needed no promotion: `Group::container` was already a group over
arbitrarily many check ids, and the family scoping is carried in the check id's own second
segment (handled in plan 03-06's `container_family_token`). Recorded as `no-change`.
