<objective>
Close VERIFICATION.md gap 1 (SC2, status `partial`): `container.mp4.fragment_duration` contains two
unresolved Critical review findings that are reachable undefined behavior from a crafted MP4, and
directly threaten SC2's "never crashes" half.

CR-01 — the inter-keyframe duration is built with a raw, unchecked `int64` subtraction of two
file-controlled `AVPacket::dts` values; a crafted file can place adjacent keyframe DTS values at
opposite ends of the `int64` range, which is signed overflow. This is the only DTS-delta site in
the codebase that does not use `detail::checked_sub`.

CR-02 — the same function then sorts the durations with a comparator built from
`compare_ticks_checked`, which folds "overflowed" into "equivalent". When that happens for some
pairs and not others, the relation is not a strict weak order, and calling `std::stable_sort` with
it is undefined behavior *during the sort call itself* — before the function's own detect-then-skip
guard is ever read.

Purpose: CONT-05 (`container.mp4.*` works) and PROBE-09 (unparseable structure degrades cleanly —
never a crash) both rest on this check being safe against crafted input, and this codebase's own
"every arithmetic site touching file-controlled magnitudes is checked" invariant has exactly one
documented violation, which is this one.
Output: a pure, testable median-duration seam that uses `detail::checked_sub` and a total order that
cannot overflow, an automated extreme-DTS regression test driving it directly, plus the two small
consistency findings in the same family (WR-02's raw byte-offset subtraction, WR-03's stale
`pass.h` comment).

Decision coverage: this plan defends D-08's bitexact-only fixture discipline — the reason the
regression test drives a pure function rather than a crafted media binary — and leaves D-01 through
D-06 as closed by their own plans (03-03, 03-09, 03-08, 03-10, 03-02).
</objective>
