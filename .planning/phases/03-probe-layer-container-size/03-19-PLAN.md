<objective>
Answer, from evidence, the question locked decision **D-GAP-01** cannot answer by itself:
does pinning one nominal ffmpeg version actually produce byte-identical fixtures on every
CI leg?

`scripts/gen_corpus.sh`'s own header and `03-14-PLAN.md`'s `<flagged_assumptions>` both state
the governing fact: `-flags +bitexact -fflags +bitexact` guarantees determinism for a **given
encoder build**, not across builds. Plan 03-16 pins four distinct binaries — Linux x86_64,
Linux aarch64, macOS arm64, Windows x86_64 — and emits a per-fixture SHA-256 listing on every
leg. This plan reads that evidence, gets an explicit decision on what it implies, and turns
the result into a standing gate.

Purpose: a golden policy declared closed on the assumption that pinning trivially yields
identical bytes is the same class of error as `03-VERIFICATION.md`'s corrected CI claims.
Output: either a committed corpus digest enforced on every leg, or a deliberate, confirmed,
loudly-announced single-designated-leg fallback — never a silent narrowing.
</objective>

<flagged_assumptions>
**A1 — Neither branch is assumed.** This plan is written so that "identity holds" and
"identity does not hold" are both complete, implementable outcomes. A finding that the four
pinned binaries do not agree byte-for-byte is a real result, not a plan failure; the named
fallback exists precisely so the plan cannot become unable to complete.

**A2 — The fallback narrows a guarantee the user locked.** D-GAP-01 kept byte-exact golden
assertions deliberately. Running them on one designated leg keeps them byte-exact but narrows
where they run, which is a scope-affecting change to a locked decision. That is why Task 2 is a
blocking decision checkpoint rather than an autonomous branch.

**A3 — Exclusion by CTest name regex, not by label.** Under the fallback branch the excluded
set is expressed as a `ctest -E` name regex over the known, stable test names, plus an asserted
excluded-count. Catch2 tag-to-CTest-label propagation through `catch_discover_tests` was
considered and rejected as insufficiently certain to bet a required status check on; a name
regex is verifiable from `ctest -N` output on the spot.

**A4 — Spec-less edge probe.** No `-SPEC.md` exists for this phase; all 32 applicable rows
returned `unresolved`, `byVerification: {explicit: 0, backstop: 0}`. None is auto-resolved,
none is dropped. In scope here: `TRUST-06` (unclassified), `TRUST-09` (unclassified), and
`DOC-03`'s `adjacency` / `empty` / `ordering` rows. The `ordering` row is answered directly by
this plan's requirement that `scripts/corpus_digest.sh` sort under `LC_ALL=C` so two runs
produce identical listings; the `empty` row by the zero-fixture guard; the `adjacency` row
concerns DOC-03 fixture pairing and is out of this round's scope. The remaining 28 rows belong
to SC1–SC4, already verified and closed. The `prohibitions` block above is authored
descriptor-less per the §B recall protocol and disposes flagged-unverified.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pinned encoder build to committed golden bytes | The corpus the goldens are baselined against is produced on each runner by a downloaded binary; if the bytes differ per leg, "byte-exact" means different things on different legs. |
| CI test-selection logic to the merge decision | What the `Test` step chooses to run determines what the required status check actually proves. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-90 | Tampering | test exclusion in the `Test` step (designated branch) | high | mitigate | An exclusion regex that quietly matches more tests than intended narrows a required check invisibly. Mitigated by computing the discovered totals with and without the regex, requiring their difference to equal a named expected constant, and failing the step when it does not — the same reasoning the step's existing test-count guard already applies to itself. |
| T-3-91 | Repudiation | silent per-leg coverage differences | high | mitigate | A green leg that skipped tests without saying so is indistinguishable from a leg that ran them. Mitigated by printing one line per excluded test, naming it and the reason, on every non-designated leg. |
| T-3-92 | Tampering | corpus bytes drifting under a stable pin | medium | mitigate | A provider re-uploading a rebuilt archive at the same version, or a generator recipe change, would silently redefine what the goldens assert. Mitigated by `tests/golden/CORPUS_DIGEST.txt` plus the assertion step: a corpus that no longer matches the committed listing fails the leg, and the file is never written by CI. |
| T-3-93 | Information Disclosure | digest listing contents | low | accept | The listing carries fixture file names and hashes of synthesized test media only; no secret or user data is present. |
