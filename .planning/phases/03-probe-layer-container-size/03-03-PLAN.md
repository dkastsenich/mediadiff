<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| media file packets -> `PacketScan`'s in-memory store | The packet count, per-packet size and stream count are all attacker-controlled properties of the input file, and each drives an allocation. |
| `--threads` / `[dir] threads` -> `WorkerPool` thread creation | A user-supplied integer directly controls how many OS threads (each with a multi-megabyte stack) the process creates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-10 | Denial of Service | `PacketScan` packet store | high | mitigate | Two independent ceilings, whichever binds first: a byte budget accounted before each append (D-01, `global_budget / threads`) and doc 02's 5,000,000-packets-per-stream cap. Crossing either sets `partial` and stops appending — the store refuses to grow rather than growing until the allocator fails. |
| T-3-11 | Denial of Service | `--threads N` thread creation (T-2-41 residual) | high | mitigate | An explicit `--threads` or `[dir] threads` above `kMaxDefaultThreads` is a usage error exiting 64 before any thread is created. D-01's byte budget does not bound thread count — each worker is a real `std::thread` with an OS-allocated stack — so this is a separate, explicit mitigation, not a consequence of D-01. |
| T-3-12 | Denial of Service | a crafted file declaring an enormous `nb_streams` | medium | mitigate | `per_stream` is sized from `AVFormatContext::nb_streams`, which libav itself bounds; each `StreamPacketScan` starts empty and grows only under the same accounted byte budget, so stream count multiplies fixed overhead, not unbounded capacity. |
| T-3-13 | Tampering | `AVPacket` lifetime across the sweep loop | medium | mitigate | One packet allocated with `av_packet_alloc`, `av_packet_unref` after every record, `av_packet_free` on every exit path via an RAII wrapper — a leak per packet over a 5M-packet sweep is itself a memory-exhaustion vector. |
| T-3-14 | Information Disclosure | resolved probe cap in `diagnostics` | low | accept | The cap is a user-chosen number and a build default; it discloses nothing about the host beyond what the invocation already stated. Accepted. |
| T-3-SC | Tampering | package installs | low | accept | No package installed; FFmpeg 8.1 pin unchanged. 03-RESEARCH.md's Package Legitimacy Audit records "not applicable this phase". |
</threat_model>
