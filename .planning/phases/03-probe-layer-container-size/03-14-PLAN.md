**Two decisions this plan makes explicitly, because the gap left them open:**

1. **Regenerate every run; do NOT cache the corpus.** A cache keyed on the generator script would
   restore fixtures produced by a *different* ffmpeg binary on a *different* run. TRUST-06's own
   precondition (03-11-PLAN.md, and `gen_corpus.sh`'s own header) is that `+bitexact` guarantees
   determinism for a GIVEN encoder build, not across builds — so both encodes must be produced by
   the same binary in the same run. A restored corpus would silently make TRUST-06 assert something
   other than what it claims to assert, which is worse than a slow step. `GENERATOR_MANIFEST.json`
   is also unusable as a cache key: it embeds a per-run timestamp and its content depends on the
   runner's own ffmpeg. Generation of ~80 short lavfi clips is minutes at most against a vcpkg
   FFmpeg build measured in tens of minutes.
2. **Generate with `scripts/gen_corpus.sh` on every leg, including Windows.** The PowerShell variant
   has no fixture recipes at all, and the workflow already sets `bash` as the default shell, so the
   Windows leg runs it under Git Bash. This is the plan's one genuine CI-iteration risk (see Task 2).
</flagged_assumptions>
