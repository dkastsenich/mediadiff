<objective>
Close VERIFICATION.md gap 2 (SC3 + SC4/DIR-06, status `failed`, empirically reproduced): the probe
memory-budget and timeout plumbing performs unchecked `int64` multiplication and an unbounded
`int64`-to-`int` narrowing on user- and config-supplied magnitudes, and an ordinary-looking flag
value overflows the budget to a negative number, which makes `packet_scan` refuse its very first
packet and forces every `size.stream_bitrate`/`size.peak_bitrate`/`size.overhead` finding to
`skipped:partial_scan` — with exit 0 and no diagnostic.

This is the phase's tracer plan: one gap closed end-to-end (bounded input, checked conversion,
wired through every command entry point, proven by a CLI-level regression test) and green before
plans 03-13/03-14/03-15 expand.

Purpose: SIZE-01's "report rate economics" and DIR-06's "peak memory per in-flight file is bounded
and asserted so `--threads N` is an honest memory knob" — both rest on budget arithmetic that is
not itself overflow-safe (D-01's memory model, whose entry point this is). The failure mode is a
false negative in this project's own P0 sense: a media diff gate that silently stops reporting.
Output: a bounded, `detail::checked_mul`-routed budget/timeout resolver used by all four command
entry points, an upper bound in the TOML loader before narrowing, and a CLI regression test that
pins "usage error OR real findings — never silent blanking".

Decision coverage: this plan implements the repair of D-01 (global budget divided by thread count)
and defends D-02 (a truncated scan makes dependent checks skip) against being triggered by a
corrupt budget rather than by a genuinely truncated scan. D-03 (estimated marker), D-04 (TSDuck
goldens), D-05/D-06 (CLI option binding) were closed by plans 03-08, 03-10 and 03-02 respectively
and are not re-implemented here.
</objective>
