  <action>
    Create `scripts/lint_bash4_builtins.sh`, a permanent scan gate that fails the build when a
    shell construct macOS's bash 3.2 does not provide appears in any `scripts/*.sh` file.

    **Scope:** every `*.sh` file under `scripts/`, including the lint itself.

    **Constructs to flag,** named explicitly in a documented list at the top of the script
    rather than buried in a regex:
    - the two bash-4 array-reading builtins (`mapfile` and its synonym), used as a command;
    - associative-array declarations — `declare -A`, `local -A`, `typeset -A`;
    - the bash-4 case-modification parameter expansions, i.e. the `,,` `,` `^^` `^` operators
      applied inside `${...}`;
    - `wait -n`;
    - `coproc`;
    - `shopt -s globstar`.

    **Explicitly NOT flagged:** `${!ARRAY[@]}` over an indexed array (valid in bash 3.2 and
    used by `scripts/capture_tsduck_golden.sh`), `+=` array append, and `[[ ... =~ ... ]]`.
    State these exclusions in the script's header so a future reader does not "helpfully" widen
    the pattern into false positives.

    **Comment handling:** strip from an unquoted `#` to end of line before matching, so that
    `scripts/check_corpus.sh`'s own two comment lines explaining why it avoids the builtin do
    not trip the gate. Document this as a line-based approximation, not a shell parser — the
    same honesty convention the three existing lints already use for their own limitations.

    **Escape valve:** a per-line marker `# bash4-allow` exempts that line, following the
    established `// dead-code-after-fail-allow` and `fixture-case-allow:` convention. The
    script's own construct-list lines carry this marker, which is how the lint can scan itself
    without matching its own pattern definitions. State that reason in the header — a lint that
    silently excludes itself from its own scan is the "gate that stops gating" shape this
    project treats as P0.

    **Required structure,** matching the three existing lints exactly:
    - `set -euo pipefail` and `LC_ALL=C`, and a `cd` to the repository root derived from
      `BASH_SOURCE`;
    - a zero-file guard: if `scripts/` does not exist, or the file enumeration yields zero
      `*.sh` files, exit non-zero with the project's established two-line refusal message;
    - the matcher extracted into ONE function used by both the self-test and the real scan;
    - a three-part self-test control clause running BEFORE the real scan on every invocation
      and printing its result first: a synthetic known-bad line containing a flagged construct
      must be reported as a violation; a synthetic known-bad line carrying the construct inside
      a comment must NOT be reported (proving the comment-stripping half works, which is the
      half most likely to silently over-match); and a synthetic known-good line must come back
      clean;
    - on violation, print one line per offending file, line number and construct name, plus a
      closing sentence stating plainly that macOS CI runs bash 3.2 and that this construct
      fails there with a command-not-found style error before any test runs — not a generic
      "portability" message. The maintainer reading a red lint needs the cause, not the
      category;
    - on success, print the number of files scanned. The count, not just a green tick, for the
      same reason the workflow's `Test` step parses its own total rather than trusting an exit
      code.
    - the script itself must contain no construct from its own flagged list (other than on
      marker-carrying definition lines), and must be POSIX-portable in its text processing: no
      GNU-only regex extensions, because it also runs under BSD tooling on macOS and Git Bash
      on Windows if anyone runs it there.

    **Wire it in.** Add a step to the `lint (ENG-16 boundary)` job in
    `.github/workflows/ci.yml`, named exactly
    `Run bash-3.2 portability lint (macOS CI guard)`, running

    `Run control-byte escaping choke-point lint (T-2-33)`. Do not rename the job.
