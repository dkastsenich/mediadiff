## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-48 | Denial of Service | mutated inputs driving any scanner | high | mitigate | This task IS the verification that T-3-19 (box-size overflow), T-3-20 (non-advancing box), T-3-25 (EBML size vint), T-3-26 (SeekHead), T-3-32 (adaptation-field length) and T-3-33 (PSI section length) actually hold — the mutation set targets exactly those fields. A regression in any of them turns this suite red. |
| T-3-49 | Tampering | `scripts/capture_tsduck_golden.sh` argument construction | medium | mitigate | Fixture paths are taken from a fixed list inside the script, never from user input or from a directory glob that could pick up an adversarially-named file; every expansion is double-quoted and the script runs under `set -euo pipefail`. |
| T-3-50 | Tampering | a pull request quietly editing a committed golden | medium | mitigate | The golden is small, extracted and pretty-printed specifically so a change is a readable diff a reviewer sees — the same reasoning D-12 records for `UPDATE_GOLDENS` being local-only. `TSDUCK_MANIFEST.json` records the TSDuck version, so a golden changed without a stated recapture is visible as a manifest that did not move. |
| T-3-51 | Repudiation | a gate that stops gating | high | mitigate | Three independent guards: CI never sets `UPDATE_GOLDENS`; a missing golden is a hard test failure rather than an implicit create; and `lint_tsduck_goldens.sh` carries a zero-file guard plus a self-test control clause so a lint that scans nothing cannot report clean.
