  <action>
Author `tests/integration/check_static_link.cmake` as a standalone CMake script (run via `cmake -P`, not included into the build) that takes the executable path as a `-D` define and inspects its dynamic dependencies.

Dispatch on the host platform: on Linux use the shared-library lister, on macOS use the Mach-O dependency lister, on Windows use the MSVC linker's dependents dump. In each case capture the tool's output and fail with a FATAL_ERROR listing the offending lines if the output names any FFmpeg shared library — match on the libav and libsw family prefixes, not on a single library name, so a build that statically linked three of the four and dynamically linked the fourth is still caught.

Two failure modes must be handled explicitly rather than absorbed. First, if the inspection tool is not found on the host, the script must FATAL_ERROR stating that the check could not run — it must never report success by default, because a verification that quietly did not execute is indistinguishable from one that passed, which is the exact failure this layer exists to prevent (see this plan's third prohibition). Second, do not use a command-substitution pattern that swallows the tool's own nonzero exit into a default value; let the tool's failure propagate and fail the script, since a tool that errored produced no evidence either way.

Do not assert the total absence of dynamic linkage. The platform CRT, libc and the C++ runtime remain dynamically linked on every one of these triplets by design, and asserting otherwise would produce a permanently red check that says nothing about the requirement. The requirement is specifically that no FFmpeg runtime install is needed.

Register the script from `tests/integration/CMakeLists.txt` as a CTest test named `static_link`, invoking the CMake executable in script mode and passing the built executable's path through the same generator expression used for the compile definition in Task 01-02-T1. Keep it a CTest test rather than a build step so it participates in the per-wave `ctest` sampling loop without slowing every incremental build.
