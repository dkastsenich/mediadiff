<objective>
Land Windows text handling at the foundation, where locked decision D-04 requires it: UTF-16 command-line arguments converted to UTF-8 exactly once at the process entry point, all internal strings UTF-8, mediadiff's own file I/O routed through a single `src/util/fs.h` shim, a UTF-8 active-code-page manifest as belt-and-braces, and virtual-terminal output enabled before anything is written.

Research resolved D-04's open verification item in the negative and it is treated as settled here: libavformat converts UTF-8 paths to UTF-16 internally on Windows via its own file-open chain, traced through the FFmpeg source. The custom AVIOContext wrapper stays deferred and must not be built. `src/util/fs.h` covers mediadiff's own I/O only.

Purpose: this is the single most expensive thing in the phase to retrofit. Every file-opening site in Phases 2 through 7 inherits the shim; adding encoding handling after those 100-plus requirements land means touching all of them. D-04 is rated costly for exactly this reason.
Output: `src/util/fs.h`, the Windows entry point in `src/cli/main.cpp`, `app.manifest`, and a non-ASCII round-trip test that runs on every triplet.

Author `src/util/fs.h` inside `namespace mediadiff` as the single site where encoding conversion happens for mediadiff's own file I/O.

On Windows, expose `utf8_to_wide` and `wide_to_utf8` implemented over the platform's multi-byte/wide conversion functions with the UTF-8 code page constant, and `fopen_utf8` implemented over the wide-character file open. Both conversions must be error-checked and must fail rather than substitute: request the strict conversion behavior that makes the platform reject an unconvertible sequence instead of replacing it with a default character, and return an empty-or-failure result the caller can detect. Silent substitution is prohibited by this plan's first prohibition, and the reason is concrete — a substituted character means opening a different file than the user named while reporting success, which in a diff tool produces a confident wrong answer rather than an error.

Handle the empty-input case explicitly before calling the conversion function. The conversion function returns zero both for a zero-length input and for an error, so the two are indistinguishable from the return value alone; treat an empty path as a caller error and return failure without calling into the OS.

On every non-Windows platform, `fopen_utf8` is a direct passthrough to the standard file open, because those platforms already take byte-oriented UTF-8 paths. Keep the same signature on both branches so no caller ever writes a platform conditional — that portability at the call site is the whole purpose of the shim, and it is what makes Phase 2 through Phase 7 inherit correct behavior for free.

Hold no static, global or thread-local state anywhere in the header. Phase 2 introduces a bounded worker pool across files and will call into this shim from several threads; the shim being stateless today is what makes that safe, and it must stay that way.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS command line → `mediadiff` argv | The single point where externally supplied text enters the process. On Windows the native form is UTF-16 and the conversion happens here, once. |
| mediadiff UTF-8 path string → OS file API | Where an in-process string becomes a filesystem operation. A conversion defect here means operating on a different file than the one named. |
| console host → `mediadiff` stdout | Output-mode negotiation. Not a security boundary, but the same entry point owns it and ordering matters. |
