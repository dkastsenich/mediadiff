<objective>
Establish the repository shape every later phase inherits, and make two of this project's structural invariants mechanical rather than aspirational.

The first is the library boundary (D-07): the engine writes nothing to standard streams and never exits the process, all rendering and process control living in the CLI. That invariant is free to enforce against near-empty targets and painful to impose after Phase 2's 48 requirements land, so the lint that enforces it ships now, against a tree where it currently has nothing to catch.

The second is fixture provenance (D-08): the corpus generator records the exact identity of the ffmpeg that produced each fixture, because bitexact flags make an encoder deterministic for a given build and not across builds. Without that record the determinism claim is not merely unverified, it is uncheckable.

Purpose: both are cheap now and expensive later, and both are the kind of thing that quietly stops being true if nothing mechanically holds it.
Output: the doc 00 section 7 directory tree, `scripts/lint_eng16.sh`, `scripts/gen_corpus.{sh,ps1}`, and the project's licence, notice, ignore and format files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| system `ffmpeg` CLI → `tests/fixtures/` | An external tool's output becomes the project's test corpus and its recorded provenance. The tool is developer-supplied and unpinned by deliberate decision (D-08), so its identity is data the manifest must capture rather than a constant. |
| library-side source → standard streams / process exit | The architectural boundary D-07 exists to hold. Not a security boundary, but the lint that guards it is a gate, and a gate that cannot fail is a security-relevant failure mode in its own right. |
| repository working tree → git history | Where a media binary, a generated artifact, or a build output would become permanent if the ignore rules are wrong. |
