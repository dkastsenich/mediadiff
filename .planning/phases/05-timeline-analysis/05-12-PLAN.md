The phase's performance gates: instruction-count measurement under cachegrind on a ten-minute 1080p
reference file, a ratchet against a committed baseline that blocks a regression, a wall-clock number
that is recorded and never asserted, and the two requirement amendments that make all of it honest.

Phase 4 already proved that wall-clock on a shared runner cannot carry that weight — its own measurement
of this workload swung 33-53%. D-13 through D-16 answer it with a measurement that is near-deterministic
on a shared machine, a gate that tracks the direction of travel rather than an absolute ratio nobody can
meet without optimising a pass this phase does not own, and a history that lives in git.

amendments to `PERF-03` and ROADMAP SC5.

<flagged_assumptions>
**A1 — PERF-01's probe edge is a `concurrency` row, authored above as a BACKSTOP truth.** The probe asks
"if interrupted or run in parallel, what is guaranteed?". For a wall-clock measurement that is
deliberately never asserted, the honest answer is: nothing is guaranteed under parallel load, which is
precisely why D-13 refuses to gate on it. That is recorded as a `verification: backstop` truth rather
than as an explicit acceptance criterion, because there is no assertion that could confirm it.

**A2 — PERF-03's probe edge row is `unclassified` and stays unresolved.** The deterministic edge probe
returned one `unclassified` row for PERF-03, `status: unresolved`, `verification: null`. Per the
spec-less fallback protocol it is never auto-resolved with a backstop and never dismissed, so it is
surfaced here. The planner's reading is that the real edge is **which baseline the ratio is taken
against** — Phase 4 measured 43-53% parser overhead precisely because the baseline pass is very cheap —
and D-14's amendment answers it by naming the measurement basis explicitly. That reading is an
assumption, not a resolved edge.

**A3 — valgrind's availability on the hosted runner is confirmed absent, not confirmed installable.**
`05-RESEARCH.md` verified against the `ubuntu-24.04` runner image's own README that valgrind is not
preinstalled, and confirmed `1:3.22.0-0ubuntu3` is an installable candidate in an Ubuntu-family apt
cache (its assumption A2). Whether the runner's apt mirror resolves the same version at CI time is not
testable from here. The script's missing-binary guard is what turns a failed install into a loud failure
rather than a silent skip.

**A4 — instruction-count determinism is D-13's own locked premise.** `05-RESEARCH.md` assumption A5
records that it could not be re-verified from a local sandbox without CI access. `PERF_RATCHET_TOLERANCE_PERCENT`
exists so a small, genuine run-to-run wobble does not produce a false regression; its value is chosen in
Task 2 from the first real CI observations and recorded with them, not guessed here.
</flagged_assumptions>
