<objective>
`timeline.jitter` and `timeline.vfr_profile`: sigma and maximum deviation of the interval distribution
on CFR streams, and a grid-relative interval histogram that means the same thing in MP4 and in Matroska.

Purpose: ROADMAP SC3 is explicit that these must use "the same shared interval statistics
`video.frame_rate.measured` consumes, not a second implementation", and D-06 is explicit that doc 04's
literal tick bins cannot be compared across containers. This plan is where the shared cadence primitive
earns its keep, and where the project's no-float rule meets a statistic that classically wants a square
root.
Output: a portable integer square root in `core/rational.h`, two registered checks with `--explain`
docs, a jitter fixture and an LGPL-clean VFR fixture, and the DOC-04 declared sets.
</objective>

<flagged_assumptions>
**A1 — the fixed-point sigma representation is a Discretion item decided here.** `05-CONTEXT.md` leaves
"the fixed-point representation of the least-squares fit and of jitter sigma" to the planner, requiring
only that there be no floating point, no float square root, and a byte-identical result across
platforms. The decision: accumulate the sum of squared deviations in the 128-bit accumulator plan 05-02
landed, take a portable integer square root of the scaled variance, and publish sigma as an exact
`RationalValue` whose denominator is the fixed scale `2^kJitterSigmaFixedShift`. Sigma is therefore a
truncated-toward-zero fixed-point value, not a rounded real — stated in the code and in the check's
`--explain` text so nobody reads more precision into it than exists.

**A2 — the VFR fixture recipe is LGPL-constrained and not upstream-tested.** `05-RESEARCH.md` confirms
doc 04's suggested `mpdecimate` is GPL-gated (`mpdecimate_filter_deps="gpl"`) and will not exist in the
`win64-lgpl` Windows pin, and that `decimate` (LGPL-2.1+) and a `select`/`setpts` chain are clean
alternatives — but assumption A3 records that no generated fixture's actual `vfr_profile` was measured.
Task 3 must GENERATE the fixture and PROVE it classifies VFR against the real binary before any test
asserts on it; if the first recipe yields a stream the amended `derive_cadence` still calls CFR, iterate
the recipe and record which one worked.

**A3 — TIME-05's three probe edges are authored in plan 05-03's `must_haves`** (adjacency at the
one-tick grid boundary, empty at fewer-than-two intervals, ordering under a shuffled read order), where
the amended `derive_cadence` that owns all three actually lives. They are not repeated here; this plan
consumes that behaviour rather than defining it.
</flagged_assumptions>
