<objective>
Amend the shared cadence derivation so CFR/VFR is decided by grid conformance and the measured rate is
derived from the span (D-05), fixing a false positive that is shipped today: a 29.97 fps MP4
stream-copied to Matroska compares as `warn video.frame_rate.measured`, 29.970 versus 30.303, under
`--profile remux`.

Purpose: false positives are P0 for this project — "a diff tool that cries wolf gets muted, and a muted
gate is worth nothing". Matroska's 1 ms timebase stores NTSC frame intervals as 33/33/34 ms, so the
mode interval is 33 ms and the mode-derived rate is 30.303 fps. Deriving the rate from the span makes
the same content measure the same number in both containers. Phase 4's own A1 note anticipated exactly
this: "if execution ever finds real fixtures where exact-tick comparison misclassifies genuinely-CFR
content, that is a finding to raise, not a silent widening."
Output: amended `src/probe/cadence.{h,cpp}` with the amendment recorded against D-07, a re-baselined
unit suite, a committed NTSC remux fixture pair that proves the fix, and updated `--explain` text.
</objective>
