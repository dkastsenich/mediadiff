<objective>
Fix WINDOWS #28 as a false positive (UD-2).
- Make timeline.vfr_profile's binning aware of sub-tick quantization, and timeline.jitter's sigma too.
- Replace the test that enshrined the false positive with a whole-report NTSC assertion.

Purpose: D-06 made the bins grid-relative so that the same content bins identically across timebases.
- A 29.97 fps stream stored at Matroska's 1 ms timebase cannot land exactly on its 33.367 ms ideal.
- Its 33/34 ms alternation is the container's rounding, not jitter.
- Today every one of its intervals lands in one_tick, against 100% on_grid for the MP4 original, and jitter warns.
- UD-2's rule: a deviation smaller than one tick of the stream's own timebase is representational rounding. It counts as on_grid and contributes nothing to sigma.

**--json / snapshot contract impact** (the release has not shipped, so bin meanings may change; stated here and in both docs):
- `timeline.vfr_profile` histogram:
  - `on_grid` now means "deviation from the ideal is below one tick" (previously "exactly zero").
  - `one_tick` now means "at least one and below two ticks" (previously "above zero, up to one tick").
  - For streams whose ideal interval is an integer tick count, every bin count is unchanged.
- `timeline.jitter` value: sigma is now measured from the exact ideal interval rather than the mode interval, with sub-tick deviations zeroed. For a CFR stream whose ideal equals its mode interval, the value is unchanged.
- New evidence keys:
  - `timeline.vfr_profile`: `sub_tick_intervals`.
  - `timeline.jitter`: `deviation_reference` (`"ideal"`), `ideal_interval_num`, `ideal_interval_den`, `sub_tick_intervals`.
- `max_abs_deviation_ms` keeps its key, and is now computed from the zeroed, fixed-point deviations.
- Snapshots taken before this plan compare against new ones with these meanings changed. Reference snapshots that contain these checks must be re-taken.

Output: the new bin and sigma contract, unit tests, docs, the NTSC whole-report assertion, re-measured declared sets, and #28 closed.
</objective>

<flagged_assumptions>
**Edge-probe items assigned to this plan (unresolved in the fallback report, surfaced here, never dropped):**
- **TIME-05 / adjacency** ("When two things are exactly equal or just touch, do they merge, collide, or separate?")
  - A deviation of exactly one tick (|Q| == den) is NOT sub-tick. It lands in one_tick, never on_grid. The boundary is strict below, inclusive above.
  - A deviation of exactly two ticks (|Q| == 2*den) leaves one_tick and cascades on, which preserves integer-ideal behavior.
- **TIME-05 / empty** ("What is the result for empty, single-element, or null input?")
  - An empty interval list still gives nullopt, and the caller degrades to insufficient_data, as today.
  - A single interval equal to the ideal gives sigma 0, one on_grid.
  - A stream where every interval is sub-tick reports sigma 0, max_abs_deviation_ms 0, and sub_tick_intervals equal to considered_intervals.
- **TIME-05 / ordering** ("When elements compare equal, is output order specified and stable?")
  - Bin output order is the existing std::map key order. Sigma is order-independent: it is a sum of squares.
  - Neither changes with this plan.

**A1: sub-tick zeroing is applied to sigma terms, not only to bin membership.** UD-2 says a sub-tick deviation "contributes nothing to jitter sigma". A deviation of 1.4 ticks therefore contributes its full 1.4 ticks, not 0.4. Rounding is removed only below the one-tick threshold; nothing is subtracted above it.

**A2: moving sigma's reference from the mode to the ideal can change the jitter trigger fixture's sigma value.** It happens wherever that stream's mode differs from span/count. Task 3's full-suite run and the doc03 coverage test prove the trigger still fires. The SUMMARY records the before and after sigma for timeline_jitter.mp4.

**Perf flag:** this plan changes the per-interval work of both checks on every input, including the MP4 perf reference. That work is one extra remainder and one fixed-point division per interval. Instruction counts may move; 05-24's designated-leg run is where the ratchet is confirmed.
</flagged_assumptions>
