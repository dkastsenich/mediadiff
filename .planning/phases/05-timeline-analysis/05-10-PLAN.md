<flagged_assumptions>
**A1 — trajectory storage is a Discretion item decided here.** `05-CONTEXT.md` leaves "trajectory storage
for TIME-08 — evidence versus a new `Value` alternative" to the planner, noting that the compared values
are rate and pattern (D-04) and that evidence already survives the snapshot round trip. The decision:
store the K entries in `Measurement::evidence`. `05-RESEARCH.md` verified the round trip exists
(`src/core/snapshot.cpp` reads and writes `evidence` directly); a new `Value` alternative would require a
new serializer arm, a new comparator arm and a report-schema bump to store something no comparator reads.

**A2 — the fixed-point least-squares representation is a Discretion item decided here.** The requirement
is no floating point, no float square root, byte-identical across platforms, with overflow discipline
through `core/rational.h`'s checked helpers. The decision: zero-base `x` at the first checkpoint,
accumulate `Sum(x)`, `Sum(y)`, `Sum(x^2)`, `Sum(xy)` in the 128-bit accumulator, and produce the slope as
an exact rational (numerator and denominator each narrowed with a range check) rather than a
pre-divided value. The rate in ms/min is that rational scaled by exact integer factors.

**A3 — the step-detection rule is transcribed, not invented.** Doc 04 §3.4: "any single residual step >
3x epsilon with stable plateaus on both sides -> `step` (report the step time)". "Stable plateaus" is
made concrete in Task 1 as: every residual before the step lies within epsilon of their mean, and every
residual after it lies within epsilon of theirs. That concretisation is the planner's, is stated in the
code comment as such, and is pinned by a unit case in both directions.

**A4 — the linear-drift fixture's expected rate is measured, not assumed.** Doc 04 §5 predicts
`asetrate=48048,aresample=48000` yields "rate approximately +60 ms/min". Task 3 must measure the actual
rate the built binary reports on the generated fixture and assert against THAT measured value, recorded
in the SUMMARY — a fixture asserted against a predicted number is a fixture that fails for the wrong
reason.
**AA5 — the `one-way` reversibility rating here has NO preceding `checkpoint:decision` in this plan, by
design.** `05-CONTEXT.md` rates D-04 one-way because check IDs are forever and a rename needs an alias plus a deprecation cycle. Both are
check-id and stored-shape decisions, so the natural gate is the phase's check-roster / snapshot-contract
checkpoint, which plan 05-01 Task 1 runs once for the whole phase — the same shape Phase 3 and Phase 4
both used. A structure check that expects the gate inside this plan will emit a warning here; that
warning is expected and the gate is 05-01 Task 1, not a missing checkpoint.
</flagged_assumptions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| demuxed timelines → checkpoint construction | attacker-controllable timestamps determine every `t_v(k)` and `t_a(k)` |
| checkpoint values → least-squares sums | crafted magnitudes drive a sum of products that classically overflows |
| trajectory → fingerprint → snapshot | a K-entry array enters committed snapshot files |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
