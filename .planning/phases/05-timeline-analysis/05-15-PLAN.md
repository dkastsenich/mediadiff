<objective>
Give ts_scan the container truth that Gap 4 needs: per-PES PTS/DTS presence and values, read from MPEG-TS PES headers. Add a pure join helper that later substitutes that truth for libavformat's read-back DTS inference.

Purpose (UD-3):
- Keep doc 04's `<=` dts_monotonic rule, and fix its input.
- The false tie on timeline_start_shift.ts is fabricated by libavformat's `compute_pkt_fields`, which re-guesses DTS with a one-frame lag because the stream copy dropped the MPEG-4 VOL. The file's own PES headers carry PTS only, which per ISO/IEC 13818-1 means DTS == PTS.

Output:
- A bounded PES timestamp seam in `src/probe/ts_scan.{h,cpp}`.
- A pure `detail::apply_container_dts` join.
- Unit tests.

This plan closes the data half of Gap 4. 05-20 wires the join into the orchestrator, so every DTS consumer (dts_monotonic, size.stream_bitrate, cadence's DTS fallback) sees the container value, and it corrects the declared sets.

Why this plan is independent of 05-14: disjoint files and no shared symbols. It runs in wave 13 beside 05-14. Execution is still sequential on one branch.
</objective>

<flagged_assumptions>
**Edge-probe item assigned to this plan (unresolved in the fallback report, surfaced here, never dropped):**
- TIME-04 / unclassified: "unclassified, review manually". This plan's reading, as the input contract for dts_monotonic:
  - A decode timestamp is container truth when the PES header supplies it, or supplies PTS alone.
  - A packet the demuxer split out of a multi-frame PES (no `pos`, no PES header of its own) keeps the demuxer's value, because the container carries no timestamp for it.
  - A genuine DTS tie or regression written in PES headers still counts; the `<=` rule is unchanged.

**A1: libavformat's `PacketRecord::pos` for an MPEG-TS packet is the byte offset of the 188-byte TS packet that carries the PES start.** Planning-time evidence: 100 of 100 video packets on timeline_start_shift.ts join on pos plus PTS. For 192-byte (M2TS) and 204-byte strides, ts_scan's recorded offset is the sync-byte position. Task 3 measures `tests/fixtures/ts_192.ts` and `tests/fixtures/ts_204.ts` and records the join rate. If the relation there is a constant shift, record it; do not adapt the join in this plan. Unjoined packets keep the demuxer's value, which is no worse than today.

**A2: the four-bit prefix before each PTS/DTS field ('0010', '0011', '0001') is not used to reject a header.** Only the three marker bits of each 5-byte field are validated. Real muxers are known to write the prefix loosely, while the marker bits are what make the bit layout unambiguous.
</flagged_assumptions>
