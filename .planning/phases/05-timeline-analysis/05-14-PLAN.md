<flagged_assumptions>
**Edge-probe items assigned to this plan (unresolved in the fallback report, surfaced here, never dropped):**
- TIME-06 / boundary: "What happens exactly at each min/max/threshold?" This plan's answer: 0 samples converts to 0 ticks. A sample rate of 0 or below, or a non-positive timebase member, gives no conversion and basis raw. The tie case, exactly half a tick, rounds away from zero, and a unit test pins it.
- TIME-06 / precision: "Where can precision loss or rounding occur, and what is the contract?" This plan's contract: `ticks = samples * tb.den / (sample_rate * tb.num)`, rounded to nearest with ties away from zero. That is the same rounding `av_rescale_q`'s default `AV_ROUND_NEAR_INF` applies, and it is done with checked integer math, never floating point. The residual error is at most half a tick, a constant shift applied identically to every drift checkpoint, so it cannot change a rate or a pattern.
- TIME-09 / unclassified: "unclassified, review manually". This plan's reading: `priming: unknown` sides are untouched, because `resolve_priming` still returns 0 samples and the raw basis. The new `rescale` field only appears when priming is known.

**A1: the MP4 -> TS pairs' av_drift verdict is expected NOT to move.** Snapshot evidence gathered at planning time shows `timeline_start_shift.ts` and `timeline_avoffset_unknown.ts` report `priming.state unknown`, `comparison_basis raw` and `samples 0`, so D-10 compares that pair raw-to-raw. The verification report assumed priming survived the remux; the evidence says it does not. Task 2 records this with evidence rather than assuming it.
</flagged_assumptions>
