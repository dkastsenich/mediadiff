<objective>
The two structural-integrity counts doc 04 §2 defines: `timeline.dts_monotonic` and
`timeline.pts_unique`, computed per stream over the shared packet array with the absent sentinel
excluded rather than counted.

Purpose: these are the cheapest possible checks and the easiest ones to get subtly wrong — a
sentinel counted as a value turns a stream with no timing into a perfect score, and a TS stream
analysed before the 33-bit unwrap reports one violation per wrap. Both failure modes report a number
where the honest answer is a skip or a zero, which is this project's P0 class.
Output: `src/analyzers/timeline/monotonic.cpp`, two registered checks with `--explain` docs, crafted
`setts` fixtures, and the DOC-04 declared sets.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| demuxed DTS/PTS → violation counting | attacker-controllable int64 values drive the comparison and the sort |
| TS raw timestamps → unwrap → counting | a crafted wrap sequence can be made to look like a monotonicity break, or vice versa |
| fixture recipe → committed corpus digest | a recipe change alters bytes a byte-exact golden asserts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-18 | Tampering | a crafted TS stream whose wraps are counted as monotonicity violations, burying a real break in noise (or the reverse) | high | mitigate | the unwrap runs FIRST on `ContainerFamily::ts` and the basis is recorded in the `unwrapped` evidence flag; Test 6 pins it, and `UnwrapResult::overflowed` maps to `insufficient_data` rather than a count |
| T-05-19 | Tampering | absent sentinels counted as values, so a timing-less stream reports a perfect score and a real regression is hidden | high | mitigate | sentinels are excluded from the axis view and the excluded count is published in evidence; Tests 4 and 5 assert both the pure-absent and the mixed case |
| T-05-20 | Denial of Service | a 5,000,000-packet stream making the duplicate-PTS detection quadratic | medium | mitigate | duplicates are found by sorting a local index view once and scanning adjacent pairs — O(n log n), bounded by `kMaxPacketsPerStream` |
| T-05-21 | Tampering | a GPL-gated bitstream filter in a fixture recipe producing nothing on the `win64-lgpl` Windows pin, emptying the gate | high | mitigate | `setts` is confirmed LGPL-2.1+ with no `gpl` dependency; an acceptance criterion greps `gen_corpus.sh` for the GPL-gated names and requires zero, and Task 1 proves the crafted sequence landed by read-back |
| T-05-22 | Tampering | a locally regenerated pre-existing digest line replacing a designated-leg hash | high | mitigate | `scripts/lint_corpus_digest_provenance.sh` runs in Task 1's `<verify>`; new names go to the provisional ledger only |
| T-05-SC | Tampering | dependency supply chain | low | accept | no npm/pip/cargo/vcpkg package is added by this plan (`05-RESEARCH.md` § Package Legitimacy Audit: not applicable to this phase) |
</threat_model>
