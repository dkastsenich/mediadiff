The assumption-delta detector fired (`detected: true`). The general representation it points at is **the shared per-stream timeline packet view**.

Today, "a stream's timestamps" means `StreamPacketScan::packets`, read raw by each analyzer. Under this plan it means the packets as the timeline defines them: unwrapped per doc 04 section 1.2 on MPEG-TS, epoch-aligned across streams, and identical storage on every other container.

- **Noun (now primary):** `TimelinePacketView`, obtained through `make_timeline_packet_views` (per file) or `make_timeline_packet_view` (per stream).
- **Decision:** `promote`.
  - Every timestamp-derived consumer migrated in this plan and in 05-18 reads timestamps only through the view.
  - Raw `StreamPacketScan::packets` becomes the non-TS special case the view borrows; it is no longer an input these consumers read directly for timestamps.
  - Adding the view alongside raw reads would leave the next consumer free to reintroduce the wrap bug. That is exactly how #26 grew to cover a fifth file (av_sync.cpp) unnoticed.
- **Invariant test (accepted, lands in 05-18):** the whole-report assertion on timeline_ts_nowrap.ts vs timeline_ts_wrap.ts. It goes red the instant any consumer reads raw wrapped timestamps again, because every wrong-axis read on that pair surfaces as an undeclared non-pass finding.
</assumption_delta_decision>
