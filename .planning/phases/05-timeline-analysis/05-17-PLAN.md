<objective>
Make the declared duration members correct on a genuinely wrapping MPEG-TS file.

05-06 set `AVFormatContext::correct_ts_overflow = 0`, so that this project's asymmetric unwrap sees the real 33-bit wrap. A side effect is that libavformat's own duration estimation, `AVStream::duration` and `AVFormatContext::duration`, is corrupted on a wrapping file, while being byte-identical on every non-wrapping one. Measured at planning time on timeline_ts_wrap.ts:

| Duration | With correct_ts_overflow = 0 (today) | With libavformat's default correction |
|---|---|---|
| Video | 180000 ticks | 360000 ticks |
| Audio | 173452 ticks | 348995 ticks |
| Container | 2.023 s | 4.023222 s |

The default-correction values are exactly the nowrap file's.

Fix: only when the packet scan shows a wrap, re-open the file once with the default correction and take only the duration fields from it. If that is not possible, withhold the declared members rather than compare corrupt ones.

Purpose: Gap 2 (SC2), the timeline.duration triple.
- 05-16 made the computed member wrap-transparent.
- This plan fixes the two declared members, which also feed av_sync's declared spans.

Output: the re-probe in `DemuxSession`, its trigger in the orchestrator, a `declared_duration_source` evidence field, unit tests, and docs.
</objective>

<flagged_assumptions>
**A1: libavformat's default-correction duration fields are trustworthy on a wrapping TS.**
- Planning-time evidence: on the wrap file they equal the nowrap file's.
- Every other committed .ts fixture reports identical duration fields with and without correction.
- The re-probe's start_time is -2.000911 s, which is libavformat's own shifted-epoch view. That is exactly why only duration fields are taken (see prohibitions).

**A2: stream layout identity is (nb_streams, per-index codec_type, per-index AVStream::id).**
- On MPEG-TS the id is the PID.
- A mismatch means the second open saw a different program map, and the durations cannot be attributed. The result is `withheld_wrap_uncorrectable`.

**Reversibility:** `costly`, flagged and not gated. The re-probe is a second file open on the rare wrapping-TS path, and it adds an evidence field users will see. It is reversible code-wise, but it becomes part of the report contract.
</flagged_assumptions>
