<objective>
`timeline.discontinuities` and `timeline.discontinuities.flagged`: presentation-time jumps that are not
explained by container structure gate the merge, and the ones MPEG-TS explicitly flags are reported as
`info` — joined through a new, bounded seam on the project's one audited TS parser rather than a second
walker.

Purpose: `05-RESEARCH.md` Pattern 5 identifies this as the phase's one genuine integration gap —
`ts_scan` tracks `cc_discontinuities` per PID but records no per-occurrence offset for
`discontinuity_indicator` specifically, so nothing today can attribute a presentation jump to flagged
structure. Closing it in `ts_scan.h` rather than in the analyzer is the difference between extending a
security-audited parser and growing a second one beside it.

fixtures (one flagged, one not), and the DOC-04 declared sets.

<flagged_assumptions>
**A1 — `05-RESEARCH.md` assumption A4 is carried forward and narrowed.** The research recorded that
`PidStats` genuinely has no per-occurrence offset list for `discontinuity_indicator` (only
`first_cc_error_offset`, and only for CC errors), and asked the planner to "re-confirm scope — maybe only
`info`-severity aggregate counts are needed per doc 04, not full offset lists — before committing to the
exact struct shape". The planner's answer: doc 04's split is per-PACKET ("packets under
`discontinuity_indicator=1` are flagged structure"), so an aggregate count cannot attribute a specific
jump and a bounded offset list is the minimum that satisfies the requirement. The bound is what keeps it
from being an unbounded structure on attacker-controlled input.

**A2 — the byte-offset join is approximate at the PES boundary.** `PacketRecord::pos` is the byte offset
libav reports for a demuxed packet; a TS `discontinuity_indicator` is carried on a 188-byte transport
packet inside that PES packet's byte range. The join therefore attributes a flag to the demuxed packet
whose `[pos, next_pos)` range contains the flagged transport packet's offset. Task 2 must state this
attribution rule in code and in `docs/checks/timeline.discontinuities.flagged.md` so a user reading the
evidence knows exactly what "flagged" means here, rather than inferring a precision the join does not
have.

**A3 — the flagged-TS fixture needs a byte-level post-processing step.** The pinned `ffmpeg` mpegts
muxer exposes no option to set `discontinuity_indicator` on a chosen packet. `tools/gen_video_fixtures.py`
is this repository's existing precedent for a Python fixture generator with a `--selftest` invoked from
`gen_corpus.sh`; Task 1 follows it. `python3` is already a hard build dependency
(`find_package(Python3 3.11 COMPONENTS Interpreter REQUIRED)` in `tests/unit/CMakeLists.txt`), so this
adds no new dependency.
</flagged_assumptions>
