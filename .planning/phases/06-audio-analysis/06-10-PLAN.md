<objective>
`meta.decode_errors` — recoverable decode errors counted and compared as a gating check rather than
treated as "could not run" — plus the narrow exit-66 case that genuinely could not run, and the fuzz
smoke that keeps the new decode pass inside `PROBE-09`'s never-crash contract.

Purpose: doc 01 §11's rule as written — any mid-file decode error marks `partial:true` and exits 66 —
would make a baseline with one known-bad frame exit 66 on every future run forever. A permanently
"could not run" gate is a muted gate, and this project treats a muted gate as worth nothing. D-09
amends the rule so a candidate that GAINS corrupt frames is a regression while a file with a known,
stable defect stays comparable. This is also the first plan where attacker-controlled bytes have been
flowing into a decoder in bulk for several plans, so it is where the fuzz smoke catches up.
Output: one registered check, one narrowed exit-66 path, the amendment recorded in two places, and an
extended byte-flip smoke.
</objective>

**A1 — AUDIO-10's edge row is `unclassified` and stays unresolved.** The deterministic edge probe
returned `unclassified — review manually` for "loudness, silence detection, and hashing share a single
decode sweep per track". The planner's reading is that the real edge is what happens to the OTHER two
sinks when one packet fails to decode — the honest answer being that all three sinks see exactly the
frames that decoded and the error count records the rest, which is Task 2's Test 3. That is an assumption
about which edge the probe meant, not a resolved edge.

**A2 — the corrupt-frame fixture must produce RECOVERABLE errors, not a hard failure.** Whether a
given byte perturbation yields a recoverable error or an undecodable stream is empirical. Task 2
builds both fixtures and VERIFIES which class each falls into against the real binary before the
assertions are written; if a perturbation lands in the wrong class the recipe is adjusted rather than
the assertion being weakened to match whatever happened.
</flagged_assumptions>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-33 | Denial of Service | a crafted stream producing an unbounded stream of recoverable errors | high | mitigate | the existing wall-clock interrupt budget still bounds the sweep, and the error count is a bounded integer; the sweep ends on the budget rather than on the error stream, and a budget-ended sweep reports `partial_scan` rather than a number |
| T-06-34 | Denial of Service | a crafted stream causing a decoder hang rather than an error return | high | mitigate | `DemuxSession`'s interrupt callback is in force for the decode loop, which is the project's existing trust boundary for libav; the fuzz smoke asserts termination |
| T-06-35 | Tampering | a decode error silently producing a fabricated measurement | high | mitigate | a degraded stream reports a skip rather than a number computed from partial data (Phase 3 D-02), and the fuzz smoke asserts this for perturbed inputs |
| T-06-36 | Repudiation | an error count that resets or is overwritten within a sweep | low | mitigate | the count increases monotonically within one sweep and the first error's reason is recorded, so the report can be traced back to what happened |
| T-06-SC | Tampering | npm/pip/cargo installs | high | accept | no package-manager install occurs in this plan; every dependency is already pinned in `vcpkg.json` |
</threat_model>
