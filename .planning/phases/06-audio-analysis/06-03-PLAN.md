<objective>
The six header-pass audio stream-parameter checks: codec, sample rate, sample format, bit depth,
channel count and canonical layout — the family that makes `5.1` versus `5.1(side)` a reported
regression instead of a silent match on channel count.

Purpose: these are the cheapest checks in the phase and the ones every other audio plan's fixtures
will incidentally move, so landing them early means every later plan's declared finding sets are
written against a corpus that already reports them, rather than being re-baselined twice.
Output: `src/analyzers/audio/{analyzers.h,stream_params.cpp}`, six registered checks with their
`--explain` docs and DOC-03 fixture pairs, and the whole-report re-baselining the six cause across
the existing corpus.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-09 | Tampering | `audio.codec` / `audio.layout` string values reaching the TTY and JUnit renderers | medium | mitigate | route both through the existing sanitizing diagnostic helper the container family already uses for `meta.tags`, so a crafted codec or layout string cannot inject control bytes into a report (the T-2-33 choke point closed in 03-15) |
