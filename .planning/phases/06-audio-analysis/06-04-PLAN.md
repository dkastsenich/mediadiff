<objective>
`audio.profile` carrying the HE-AAC SBR signaling mode — explicit versus implicit — resolved in the
header pass so the value is identical whichever passes ran, with a no-decode fast path for the
explicit case and a bounded one-packet decode only for the genuinely ambiguous one.

Purpose: 06-RESEARCH.md proved against the linked FFmpeg 8.1 that `codecpar` does NOT carry the
SBR-doubled sample rate or the HE profile after `avformat_find_stream_info()` for an implicitly
signaled stream — `isom.c` falls through to the undoubled base rate, the decoder only discovers
implicit SBR while decoding a raw_data_block, and `has_codec_parameters()` can be satisfied before
any frame is decoded at all. Doc 05 §2.1's literal recipe therefore cannot work, and D-12's fallback
is the real path. Building it in the header pass is what keeps `audio.profile` pass-independent.
Output: a bounded ASC/ADTS reader, a one-packet signaling probe, and one registered check whose
value makes both HE-AAC signaling modes visible.
</objective>
