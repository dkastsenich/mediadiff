CR-03 (HIGH, undefined behavior on hostile input). A float or double sample is scaled and passed to std::llround with no finiteness or range guard. It is then negated (the INT64_MIN case) and squared. Raw float bytes also go straight into libebur128. The path is reachable from pcm_f32le/pcm_f64le, where file bytes are reinterpreted as float with no decoder clamping. The fix is a named-constant guard that stops level measurement with a reason, plus bounded normalize arms. The hash continues on the exact bytes, which remain a valid bit-exact basis.

WR-03 (substantive half). Receive-side failures were never counted toward the consecutive-error DoS bound. Keep `>`; do not change it to `>=`.

Purpose: no hostile sample value can cause UB or poison a level reading, and no hostile error pattern can evade the bound.

<flagged_assumptions>
**A1: why 32768.0.** Real float pipelines exceed 0 dBFS by a few dB at most. A sample above +90.3 dBFS (32768 times full scale) is not audio a level meter can represent: it is corrupt or hostile data reinterpreted as float. Up to that magnitude, libebur128's double-precision energy sums stay far from overflow (32768 squared times 48000 samples is about 5e13). The constant is named and appears in docs. It is a measurability bound, not a tolerance.

**A2: the receive-arm test rests on a source reading, guarded by an assertion.**
- pcm.c (lines 434-441, 624) truncates a packet to whole sample frames and returns the truncated size.
- decode.c (lines 495-499) keeps the unconsumed remainder, and the next receive decodes it and fails because it is shorter than one frame.
- The test first asserts that one such packet yields decode_error_count 1, total_samples 1, and a first_error_reason starting with "avcodec_receive_frame". If that guard fails against the linked FFmpeg 8.1, the executor stops and reports the measured counts (Rule 4) instead of weakening the test. The seam test then remains the only receive-arm proof, and that is stated.

**A3: a receive-ONLY run of failures cannot be built from outside libavcodec.** An error on a packet's first frame surfaces from send, because send decodes eagerly (decode.c 733-736). The WR-03 proof is therefore a mixed run: one receive failure followed by send failures. That is exactly the run the old code under-counted.

**A4 (folded note 3, deferred):** the float/double arms keep their existing byte-read form. Only the range handling changes.
</flagged_assumptions>
